# P3 任务图鉴实现前核查

日期：2026-11-11。用户要求参考 P2G，排查 P3 任务图鉴实现阻碍。核对源码为 `feat/mhp3-quest-catalog` 的 `2c80b3e23055b64caafc21a86440fed395ea31dc`；本轮只读原版与现有库、保存私有研究结果和文档，没有实施任务图鉴。

## 结论

**没有发现需要用户重新解包、补 EBOOT 或先重构共享图鉴才能继续的阻碍。原版输入、任务身份到资源的加载映射、清单及原文已取得可复核证据；但 P2G 已完成的报酬／支给、条件树和出场关系，在 P3 尚未达到同样的验证程度。** 下一阶段应先闭合这些本作数据契约，再定完整实施图纸。

P2G 可参考其[功能和数据边界](../../mhp2g/quest-catalog.md)、[当时的原生核查](../../../plan/archive/2026-10-24/mhp2g-records/quest-preflight.md)。借鉴的是取证、建库与交互方式；P3 的二进制布局、数值、枚举、报酬规则和解锁判定须独立验证。

## 与 P2G 相比仍需完成的工作

| 领域 | P3 的具体缺口与影响 | 处理顺序／退出依据 |
| --- | --- | --- |
| **本体目录与基础字段** | 村、集会浴场、训练、温泉、饮料的分类、特殊入口、任务类型、地图昼夜、时间／费用／点数等尚未逐字段形成完整契约。P3 任务头与记录布局已确认不同于 P2G | 以已核实身份为键，从菜单与详情消费者核对字段，再与本作独立资料交叉；保留清单重复、特殊资源和训练差异。不要直接运行 P2G 原生解析器 |
| **报酬和支给** | 奖励组、顺序、条件、首项保证、抽选次数、原始权重与概率单位，以及支给格和追加时机尚未闭合。照搬 P2G 的 16 格／首抽规则会写入未经证明的机制 | 追本作任务读取和结算／支给消费者，完成全量道具端点与组边界审计；抽选权重不当作整场概率，支给格不合并成一次获得量 |
| **关键、紧急与开放条件** | 普通菜单显示、关键集合、紧急入口、村／浴场进度、温泉／饮料完成效果和训练条件缺完整证据 | 区分前置任务、计数、进度、特殊事件及 AND／OR／否定；温泉效果和饮料解锁独立建模。先做静态说明，不扩为实时存档可接判定或解锁修改 |
| **怪物与任务关系** | 任务目标、固定配置、乱入、连续出场、小型切组及个体参数还没有完整绑定。现有 598 条出没观察有独立来源，不是任务对象 | 建立原生任务与本作怪物的显式关系，再逐条映射旧观察；同名任务按体系、难度、地图、目标等消歧。保留无法绑定项和独立资料原值，不因接入任务而删除观察 |
| **配信覆盖** | 本轮未取得原生配信包，其他宿主位置也未作穷举，因此不能认定不存在。活动和挑战有可用本作参考 | 可沿 P2G 的独立来源身份方案纳入有据记录，缺值标未收录，不编造原生编号；实际纳入范围在实施计划中明确，无须将等待配信包设为本体调查的前置 |
| **中文与来源审阅** | 930 个本体去重文本单元尚未形成任务专题审校表；配信和条件说明还需另审。已有怪物出没名仍为日文 | 使用本作原文，按已确认规则核对 GU 审定术语和项目译名；名称对应不意味着目标／委托说明、数值或条件相同。译文及审阅集合继续私有 |

标题不能担当关联键。本轮只按标题做诊断：598 条旧出没观察中，254 条仅有一个本体同名候选，167 条有多个，177 条没有精确同名候选。**这三类均不等于已绑定、冲突或不存在**；后者可能涉及配信、书写差异或其他来源范围，必须按上下文核对。

## 工程接入：可复用，但需要明确适配

共享 `QuestCatalogPage`、工具栏、列表、分页、三个详情页签与一级抽屉已经具备，P2G 的专用 repository／追加建表方式也可参考。无需先做跨作品架构重构；以下是明确的必要接线点：

- `api/catalog/types.ts`、`schemas.ts`、`ipc.ts`，以及 `desktop/preload.ts`、`ui/env.d.ts`：任务身份、搜索、facets 当前不接受 P3。按任务领域增加能力和显式 P3 分派，不能扩大通用 `CatalogGameId` 误开配装／存档，也不能落入旧作品 repository。
- `ui/components/QuestDetailDrawer/QuestDetailDrawer.tsx`：道具定位目前只对 P2G 取 `itemId`，其余取 `saveId`。P3 使用 `itemId`，开放任务前必须适配并验证跨页定位；这是未开放 P3 任务的接入缺口，未声称现有已开放功能发生回归。
- `QuestInfoSection`、`QuestRewardsSection`、`QuestUnlockSection` 和各 `P2gQuest*` 区域：当前 P2G 说明包含本作专属报酬、训练及出场规则，不能整体作为 P3 数据容器。P3 需要自己的条件、来源覆盖、温泉效果和饮料解锁区域，布局沿用共享页。尤其当前空奖励默认文案“没有普通道具奖励”，不能用于尚未收录的 P3 来源。
- `p3MonsterRepository.ts`、`p3ItemRepository.ts`、怪物页与 `P3MonsterAppearances`：接入任务 ↔ 怪物／道具的双向查询、关联搜索和命中原因；已绑定观察可进入任务抽屉，未绑定观察保留原落点。正文开抽屉、抽屉内关闭后定位，不能叠抽屉。
- 在当前完整 `mhp3.sqlite` 的副本追加任务表、关系和资料版本；验证已有业务表、非目标作品及词典输入未变。任务追加本身不触发词典重建。新构建器和公开合成测试尚未编写。

图鉴可以复用已接入的本作怪物／道具图标和共享视觉，不需把新任务图标解码设为接入前置。仍须分别验证缺库、缺任务模块、未知字段与加载失败，不能用空数组或默认“普通任务”吞掉未确认资料。

## 下一步与验收边界

建议先补 **任务基础字段及报酬／支给 → 关键／紧急和温泉／饮料／训练条件 → 怪物出场与旧观察映射** 的原生契约；同时按字段核对已冻结参考。退出依据为来源明确、身份与关联端点可审计、未知项可表达，之后再整理完整 DB → API → API 验证 → UI → UI 验证实施计划。

实现时需要以合成资料覆盖身份隔离、同名任务、训练字段差异、替代／条件奖励、支给配置和未收录状态；真实资料再检查 1440×900、1024×768 的中文、检索、前进后退与单层抽屉。P2G 和其他已接入作品需受影响回归。浏览器、Electron、Windows 包和游戏验证分别记录；本轮未执行这些验收。

本轮完成 9 次成功原生只读探针，另保留 3 次失败及修正记录：误将旧非任务对照成员纳入任务解码，以及两处未考虑零长度清单槽的探针假设，后续已修正。它们不证明原版资源损坏。8 页参考哈希、探针输入／输出、失败、原文、精确地址及局部程序集均保存在私有 `../research/mhp3/quest-preflight-20261111/`；本地审计 `audit_preflight.py` 校验全部记录并确认六库未变。

本报告是实现前调查结果，**不是完整功能验收或已经定稿的实施图纸**。恢复位置及 Git 检查点见 [Codex 交接](codex.md)；P3 运行资料仍仅限本地。
