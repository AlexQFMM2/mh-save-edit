# 道具译名词典

2026-10-10 开发工作区已接入全局“译名词典”按钮和四作道具图鉴的别名搜索。词典是一个独立的、可选的运行数据库 `data/item-terminology.sqlite`，只维护道具名称。本词典仅查询道具；技能、装备等名称正在独立的 [P2G 图鉴中文资料](mhp2g-localization.md) 中准备。P2G 已改用完整日版原文；没有批量繁简转换。未能直接对应官方名称的部分采用项目译名，用户界面展示来源，内部审校状态仅用于维护追溯。

## 显示与搜索

- 通过已确认的日文原名对照 GU 词条，采用有解包来源依据的官方简中作为显示名；详情保留本作原译名与采用来源。
- 支持首选名、各作原译名、Dex 历史译名、已有繁中名、英文名及日文名的子串搜索。结果附带命中的别名，返回当前游戏自己的道具编号。
- 词典面板可按游戏筛选、翻页、查看各作叫法与逐条来源；Escape 关闭后焦点回到触发按钮。面板不修改资料。
- 日文缺失、GU 无对应、或同名有歧义时，各作记录独立保留，不猜测身份、不按中文相似度合并。面板显示待补原因。
- `item` 是当前唯一对象类型。将来增加技能/装备应有独立类型和接入器，不得把同名对象跨类型合并，也不得把技能名称映射当作效果或阈值等同的证据。

## 身份与数据边界

`terms` 保存稳定词条 ID、对象类型、日文、首选中文及采用来源；`aliases` 保存词条的名称及游戏/来源；`members` 显式关联 `游戏 + 道具编号`，保存原译名和匹配状态。P2G 编号是原生 `item_id`，其余三作是各自 `save_id`，不能互换。日文对应只允许拉丁字母与数字的全角/半角差异，候选唯一才建立对应；保留等级前缀、圈号、标点及假名/汉字。搜索中的完整 NFKC、大小写归一化不参与身份合并。

3G、4G、GU 图鉴数据库的中文原值保留，其道具列表、详情及详情中的关联道具按词典投影首选名；调合标签按已有编号关系生成，不全局替换描述文字。配方、图标和存档数值不迁移。P2G 直接把选定名称写入图鉴，并用独立元数据保留旧称；词典缺失时仍使用这套名称。其余图鉴在词典缺失时按原数据运行，词典面板说明未安装；词典与道具身份快照不一致时拒绝使用该游戏的过期映射，并提示重新构建。

## 当前 P2G 输入

本地词典 `v6` 配套日版原文构建，1,260 件正常道具全部有日文和中文显示名，648 件完整匹配 GU。另有 69 个珠名对应 GU 日文名加孔位后缀，来源标为“GU 官方用词（省略孔位后缀）”；它们保留 P2G 独立词条和原生编号，不合并到 GU 的不同孔位道具。其余 543 件按 P2G 图鉴选定的项目译名显示，不再回退旧汉化；最后 146 件名称已补齐，尚无中文初稿的道具名称为 0。原名、新名和日文都可搜索。元数据也参与身份指纹，别名改动后同样必须重建词典。2026-10-10 按用户要求，详情、词典和展开的来源列表均不再显示“待验收”“待审校”等内部状态；显示层统一整理来源标签，旧数据库也直接生效，无须重建资料。

当前构建使用新 P2G 图鉴与另外三作当前数据库副本，不传旧 `p2g-japanese-evidence.json`。完整入口、私有快照、覆盖和验收限制见 [P2G 图鉴与中文资料](mhp2g-localization.md)。以下 Wiki 补充方式和 v1–v3 数字仅记录历史，已被完整日版来源取代，不用于新版 P2G。

把已验证的新 P2G 图鉴和另外三作当前数据库副本放在同一输入目录后运行：

```bash
node tools/build_item_terminology.mjs \
  /private/catalog-input ../research \
  ../research/generated/mh-save-edit/item-terminology/<新版本>
```

`v6` 保留 4,749 个词条；另外三作的日文修复计数均为 0。146 件新增译名逐项通过新中文、日文和旧译名搜索检查，独立 Electron 25 项检查通过。本地已备份安装 P2G 图鉴及词典，报告在 `.runtime-assets/item-terminology/electron-check-v6`，备份在 `.runtime-assets/item-terminology/pre-v6`。

## 日文列修复

三作 Dex `ID_Itm_Name.csv` 的 `Itm_Name_2` 是繁体中文，`Itm_Name_3` 才是日文。旧道具构建器把前者写入 `name_jp`，现已修正并更新构建版本键。独立构建工具只在数据库副本修复此列；仅允许原值等于旧繁中、为空或已经正确，遇到其他值中止并要求核对，不覆盖未知内容。

P2G 初版只从调合配方资料补充日文，共 253 件，因此常见道具也可能缺日文；另有一件药品使用了错误日文。补充工具从固定的 P2G 原生表与日文 Wiki 历史镜像核对：名称完全相同只是候选，还需唯一端点、持有上限和卖价相符，并检查资料列出的买价。异体字差异必须逐条保存人工核对依据，不能批量繁简转换，也不能把采集表中的局部别名推成全局同义词。Wiki 是第三方资料，输入记录保留其来源和局限。

`tools/prepare_mhp2g_item_japanese.mjs` 校验原生字段、Wiki 捕获文件哈希及字段坐标后生成独立证据文件。应用证据时逐项核对原名称、说明、数量、价格和原日文；只修复 `name_jp`，任何意外值导致整批回滚，重复应用不再改动。

怪物素材的 Wiki 持有上限常为空，不能向下填充上一行数值，也不能单凭卖价认定身份。已逐条审阅的素材允许用“原名称/说明含义 + 同作卖价 + Wiki 怪物与位阶 + 原生怪物掉落端点”补充佐证；原生掉落必须在该位阶有正概率记录，普通种/亚种使用明确的怪物编号，Wiki 已填写的持有上限和买价仍必须相符。该路径只用于显式审阅记录，空白不推成数值，也不改变获取关系或概率。

## 私有来源与重建

固定输入：

- `research/generated/mh-save-edit/terminology/versions/gu-pass-02/`：核对 manifest 中词典与 audit 哈希，逐条验证官方中文的采用证据。不要使用已淘汰的 `gu-pass-01`。
- 三作 `research/<游戏>/dex/*-dex/direct_sql/ID_Itm_Name.csv`：列 3 日文与历史译名；按已有 Dex ID 读取，不按行号。
- 四作当前运行 SQLite：已建立的游戏编号、Dex ID、原名称；P2G 的已确认日文来自其道具资料构建结果。
- `research/mhp2g/item-japanese-v2/evidence.json`：P2G 日文补充依据及所有固定输入的 SHA-256，包含上一批依据。重建时显式传入，避免从旧 P2G 快照重建后遗漏修正。

需重新准备 P2G 补充依据时执行（审阅文件和生成的证据均保存在私有研究区，证据输出不可覆盖）：

```bash
node tools/prepare_mhp2g_item_japanese.mjs \
  ../research/generated/mh-save-edit/mhp2g/pilot-r9/mhp2g-pilot.sqlite \
  ../research/generated/mh-save-edit/item-terminology/v1/mhp2g.sqlite \
  ../research/mhp2g/item-readable-observations-v1.json \
  ../research/mhp2g/item-japanese-v2/review.json \
  ../research/mhp2g/item-japanese-<新版本>/evidence.json
```

从仓库根目录执行，输出必须是不存在的新目录：

```bash
node tools/build_item_terminology.mjs \
  data ../research \
  ../research/generated/mh-save-edit/item-terminology/<新版本> \
  ../research/mhp2g/item-japanese-v2/evidence.json
```

输出包含四作修复日文后的数据库副本、`item-terminology.sqlite`、输入/输出 SHA-256 manifest 和待补审计报告。原输入不修改；失败目录标记 `FAILED.txt`，不得安装。每次更新任何一作道具身份或名称，应重新构建词典和对应副本后成套安装。数据库均须关闭连接后替换，保留旧文件以便成套回滚。

历史生成版本 `v3`：5,148 条词条；GU/4G/3G/P2G 分别有 2,906/1,214/809/249 件道具匹配到 GU 词条。`v2` 新增 23 件日文、修正 1 件日文，另有 2 件通过 G 字符宽度对应；`v3` 再补 24 件怪物素材日文，21 件匹配 GU，3 件亚种素材保留原译名。当时 P2G 共 1,260 件有效道具，300 件有日文，960 件待补；其中有日文但 GU 词典无对应的为 51 件。该日文 Wiki 快照仅收录 913 项，不能称为完整日文表；当前完整日版来源已经补齐日文，覆盖数字以上方 v6 为准。

所有生成文件、真实词条、manifest、映射及审计保持在私有研究区；本地安装的 SQLite 受 `.gitignore` 排除。当前公开运行资产包尚不含这个独立词典，公开打包白名单也未扩展。后续发行应单独准备经授权的运行资产，不把研究输入、词条 CSV 或审计放进 Git 历史。
