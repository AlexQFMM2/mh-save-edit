# P2G 存档编辑器

更新：2026-10-13。已实现 PPSSPP 日版／汉化版 P2G 存档编辑，并开放现有修改页。实现依据见 [接入前核查](mhp2g-save-preflight.md)。真实样本的应用层解密、编辑、成对保存和重读已通过；**尚未在 PPSSPP 游戏中重开修改副本**。最新检查与修复见[整体验收](mhp2g-acceptance.md)。

## 使用与共享组件

进入 P2G → 修改 → P2G · PPSSPP，选择存档目录中的 `MHP2NDG.BIN`；同目录必须有匹配的 `PARAM.SFO`。读取后选择角色。

- 复用 `SaveEditorPage`、`SaveEnvironmentPicker`、`SaveCharacterPicker`、`SavePersonalEditor`、`SaveBoxWorkspace`、`SaveSessionHeader` 和 `SaveBoxTransferDrawer`。
- 装备复用 `SaveEquipmentEditorDrawer` → `EquipmentPickerContent` → `EquipmentPickerPreview`，左侧搜索、筛选和列表，右侧图鉴详情，底栏显式应用；没有另建 P2G 装备选择页。关联详情通过相同抽屉关闭后跳转。
- 装珠复用 `DecorationEditorContent`。添加／移除仅更新抽屉草稿，点击“应用字段修改”才进入存档撤销栈，取消／Escape 丢弃草稿。
- 强化输入由共享存档字段组件 `SaveEquipmentUpgradeField` 呈现，适配器提供字段描述与上限。页面不修改子组件内部样式。
- 图鉴加入道具／装备、配装器整套加入装备箱沿用 `CatalogWriteControl` 与 `LoadoutSaveWriteDrawer`。写入只进入内存草稿；保存前可撤销。

已开放金钱、波凯点数、游戏时间、道具箱、正常武器／防具、装珠、防具强化次数、弩强化次数，以及复制、清空、CSV／完整箱子备份与撤销重做。身上装备会标识，并同步已确认的记录副本。角色名、性别与任务推导的 HR 只读；猫、任务进度修改、特殊装备类型和弩附件名称／切换尚未开放。

“保存”更新 BIN 和 SFO；“另存为”选择父目录，在其中创建新的 `ULJM05500` 子目录，并复制已有的 `ICON0.PNG`、`PIC1.PNG`。目标子目录已存在时拒绝覆盖，包括选回当前源存档目录；只有“保存”执行原位成对写回。

## 格式与数据边界

`api/save/p2g` 分别负责参数加载、双层编码、SFO、原生身份转换、图鉴解析和成对文件保存；`adapters/mhp2g.ts` 负责角色布局和装备引用同步。`SaveGameId` 扩展存档边界，旧版核心 `GameId` 不作无关扩展。

原生图鉴和逻辑配装继续使用 `weaponKey`、`armorKey`、`itemId`，不伪造 Dex 身份。只在存档转换边界按已验证的原生 dispatch 显式转换：腿／头／胸／腕／腰 = 类型 0～4，近战武器 = 5，远程武器 = 6。是否为空由独立 occupied 字节判断，类型 0 的腿甲不是空格。

记录为 12 字节。防具只修改强化低字节，弩只修改低四位，保留附件和未确认高位；弓的图鉴 typeId 为 14，不走弩强化分支。天然孔不足或超过自然强化次数只提示，编码越界才拒绝。未知记录可浏览、原样保存和完整导入导出，不能通过字段编辑猜测特殊类型。

箱子序列化容量为 1000，开放格数按两本整理书的取得标记推导为 800／900／1000，未开放尾部保留。增加书本道具不擅自改写取得标记。HR 由已核实任务表索引和完成位推导。

穿戴和预设引用按箱格号处理，不能比较相同装备记录后猜引用。修改同部位穿戴装备会同步身上副本；删除或跨部位替换穿戴装备被拒绝。未穿戴预设武器删除／跨域替换清空该预设六个引用，防具只清对应引用，保留颜色字节。换位同时交换箱格并重写穿戴／预设引用。所有关联变化同属一次撤销，批量导入失败恢复完整原草稿。切换角色必须先保存或撤销到干净状态；实际切换角色时清空撤销／重做和导入预览，避免修改当前界面未显示的角色。

## 成对保存

保存前验证原 BIN 和 SFO 都未被外部更改，备份两文件及已有图片，建立带前后摘要的持久恢复目录，再依次替换文件。落盘后重新解密、校验 SFO／BIN／游戏 SHA-1、校验引用并比较整个 payload。失败则恢复原配对；进程中断遗留的恢复目录在下次读取时恢复。恢复发现外部新增修改会保留现场并拒绝自动覆盖。

恢复目录固定为存档目录中的 `.mhp2g-save-pending`，原件备份为 `.mhp2g-backup-<时间>-<唯一标识>`。恢复只访问固定文件名，绝不信任日志提供任意路径。日志完成后先整体改名再清理，避免清理中断留下半份活跃日志。这里保证应用级恢复；不宣称 Windows 断电时目录元数据具备跨文件原子性。

仅支持已验证的 PPSSPP mode 5／SFO 标记 `0x41` 和 fuse-hash 回退格式，其他 PSP 实机模式会明确拒绝。编码算法用 Node 标准 crypto 实现；参考 mhef `8a5132fb7024103ba6271371b81060a55a437651`、PPSSPP `dd6bd1a53d38773c1d07985fcb7d2f56fcaa872c` 及本地 JP BOOT 证据。默认 mhef 的 P2G 替换表不匹配本样本，必须使用已核对的原生表。

## 私有格式资源

替换表、格式参数和 HR 位索引由冻结研究输入生成，不放入公开源码：

```bash
python3 tools/build_mhp2g_save_profile.py \
  --research ../research/mhp2g \
  --output ../research/generated/mh-save-edit/mhp2g-save-profile.json
cp ../research/generated/mh-save-edit/mhp2g-save-profile.json data/mhp2g-save-profile.json
```

构建器只解析参考文件的常量 AST，不执行参考程序，核对参考源码 SHA-256、原生 BOOT 来源和替换表互逆性。运行时只读应用数据目录中的 JSON，不依赖宿主机或 research 路径。2026-10-13 本次发行已将该文件与 P2G SQLite 加入运行资源 v5 和 v0.1.12 Windows 包；文件仍受 Git 忽略，研究输入和个人存档不发布。

- 合成测试覆盖 RFC 4493 CMAC、双层往返、BIN／SFO 损坏拒绝、类型 0 腿甲、引用同步、复制／换位、预设清理、强化高位保留、弓与弩区分、导入原子性、撤销、原生图鉴／配装写入。
- 文件测试覆盖外部 SFO 修改、两次写入之间故障、进程中断恢复、恢复时再次外部修改、完整目录另存为和拒绝覆盖。
- 共享 UI 测试覆盖选择与应用分离、装珠草稿取消、原生道具 ID、环境入口。全量回归：113 个测试文件通过、3 个按条件跳过；751 项通过、8 项跳过。后续针对共享存档 UI 的 47 项、适配器的 14 项和成对文件的 5 项回归通过（含新增的写入间外部修改场景）；类型检查和构建通过。
- 真实样本三角色均通过生产适配：280 条非空装备全部映射，1589 格非空道具；HR 为 1／9／9，箱子容量均为 1000。未修改 BIN／SFO 逐字节还原；隔离副本只修改第二角色金钱，重新解密只有目标字段内 1 字节变化，原件不变。
- Chromium 1366×768 与 1024×768 检查共享选择器、详情和装珠；主页面位置／宽度不变，无窗口横向溢出，Escape 不提交装珠草稿。

私有验收脚本、报告、截图和可供游戏重开的隔离副本归档到 `../research/mhp2g/save-editor-v1`。Windows 原 RAR／存档未修改，没有启动 PPSSPP。下一步是使用隔离副本进行游戏读档、查看金钱和装备、游戏内保存再重读的验收；未经授权不要覆盖宿主机原存档。
