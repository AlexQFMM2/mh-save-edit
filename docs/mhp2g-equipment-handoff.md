## 装备阶段先核查的内容

1. 清点武器与防具的原生记录、有效条目、占位和变体，明确图鉴身份。已有原生文本数量为武器 1,504、防具 2,096，不能直接作为最终玩家目录数量。
2. 逐字段核查攻击、防御、属性、会心、耐性、孔位及武器专属参数；复用已验收的防具技能点。旧研究中的斩味模板不直接等于实际长度，弹药模板也不直接等于可装填容量。
3. 闭合制作材料、生产／强化／派生关系、技能端点与旧道具用途；同名、同序号或相邻原生记录都不能替代显式身份对应。
4. 定向核查装备图标及资源映射。解包访问失败只能说明连接问题，不能推断游戏没有资源；未确认字段明确保留未知。
5. 以日文和本作上下文审校名称／说明。已有防具资料中仍有日文名称，不把文本绑定完成当作译文审阅完成。
6. 核查后再建立装备实施计划，沿用现有武器、防具列表、详情、派生／套装及单层关联抽屉的交互，保持 MH3G、MH4G、MHGU 的数据与行为。

以上是接手检查项，不是“装备已无阻碍”的结论。本轮未开展新的装备数据核查，也未建立未经验收的实施承诺。

## 本轮确认的译名与 UI 约定

- 日文有明确对应时优先采用 GU 官汉；无对应时按 P2G 原文和上下文拟译，保留来源。数值与机制始终归本作。
- 同名不保证同机制，效果相同也不能证明跨代物品身份相同。保留 P2G「大砲珠」的“大炮珠”名称，不因其孔位、技能点与后作炮术珠相同而合并；跨代命名沿革不作为图鉴实施前置。
- 图鉴列表查询只随搜索、筛选、排序、分页、定位条件及游戏变化。选中条目、详情页签和随 URL 改变的回调不能再次触发整列表查询。待返回响应必须读取最新选择，避免自动首选覆盖新导航。
- 正文关联打开唯一一级 portal 抽屉；抽屉内关联先关闭再跳转定位。防具图鉴接入后须兼容技能页已有 `equipment=armor_<部位>:<编号>` 链接。
