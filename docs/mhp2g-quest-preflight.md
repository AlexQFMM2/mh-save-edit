# P2G 任务图鉴接入前核查

调查快照：2026-10-12。此文保留接入前的调查结论；后续实现已完成，当前入口见[任务图鉴说明](mhp2g-quest-catalog.md)。

本轮只做原生追踪、身份对照和接入边界核查，未实现任务页面、未修改运行数据库、未提交或发布。继续限定 P2G，不改 MH3G / MH4G / MHGU。

## 当前结论

**静态任务图鉴的原生资料主要阻碍已清除，可以据此制定实施计划。** 目录、身份、Wiki 对照、奖励与支给品条目、大小型怪物关联已经打通；本轮继续追通了继承旧档标志、介绍事件标志、训练首项奖励和怪物分组切换。用户已明确没有配信任务包，并同意“Wiki 有就加”；无需继续等待配信文件。

当前可整理为 **450 个本体任务 + 52 个 Wiki 配信任务，共 502 条候选目录**。52 条是现有快照覆盖数，不宣称覆盖历史上的全部配信。

此前几项疑点的原因是原生调用链尚未追全，尤其漏查了创建角色／继承旧档模块；现已找到相应数据和代码。剩余工作是中文校对、数据构建、关联迁移和页面实现。本轮结论覆盖静态图鉴所需条件与已核实的出场规则，不等于完整复刻游戏 AI、存档可接判定或整场奖励概率。

## 关键、紧急、解锁与轮换

- 原生关键数组有 **77 项**，Wiki 标记有 79 项。差异已解释：村上位金银火龙 `11211 / 11212` 是关键任务 `11213` 的前置，原生条件 145 同时检查两者完成。保存“原生关键”与“关键前置”两种关系，不漏掉金银火龙。
- 菜单紧急插入分支确认 **21 项**。Wiki 行内紧急符号覆盖其中 19 项；不能只依赖符号。混合清单 5321 还含寻宝等内容，不能整表标紧急。`11226 モンスターハンター` 是全清特殊任务。
- 普通菜单特殊显示函数已生成有界路径记录：551 个资源中 89 个任务有特殊分支，涉及 59 个集中条件。前置任务、指定任务集合、村任务全清和累计计数等判断已定位。“无特殊限制”不等于满足位阶或紧急入口。
- 训练开放使用独立位图，已提取 **27 个条件分支，绑定全部 47 个训练任务**：基础／武器菜单、指定村任务后的开放、前置训练与狩猎计数、G 位任务完成、集团训练条件。
- 训练辅助函数 `0x08857000` 只要求五种武器中任一种完成，**不是全武器完成**。低位个人训练检查返回事件中的任务 ID，没有读取完成位；Wiki 的“允许放弃返回”说明单独保留来源。
- `0x0886f654` 确认部分永久标志按任务位阶和怪物身份设置，涉及上位黑龙／红龙与 G 位钢龙、炎王龙、霞龙、黑龙、红龙。不能用“某任务完成”统一替代怪物讨伐条件。
- `0x08855350` 更新轮换标志，游戏任务模块存在直接调用。若干成对标志采用随机取余分支，部分使用模 10，不能统一写成模 12。当前采用“解锁后随机／轮换出现”的已证实含义，不声明统一出现概率和刷新时机。

本轮补齐的标志写入链：

- **208、210、218 是继承 P2 旧存档时计算的标志。** DATA 44 的继承入口调用 BOOT 旧档读取函数，明确使用 `ULJM05156 / MHP2ND.BIN`，转换后由 `0x09a60588` 写入这些标志。它们并非普通任务返回时反复更新的缓存；此前只查任务／大厅模块会漏掉该入口。
- 208 检查指定的 76 个旧村任务全部完成，参与 `10510「最後の招待状」` 的开放条件；210 检查指定的 34 个旧集会所任务全部完成，参与六个上位钢龙／炎王龙／霞龙任务的开放条件。
- 218 检查七个怪物家族各狩猎至少 10 次，家族计数包含讨伐和捕获，参与 `2224「終末の時」` 的开放条件。三者均保留所在条件表达式；尤其 218 所在 OR 分支之外仍有门槛，不能写成“有此标志即无条件开放”。
- **357、358 是介绍事件结束标志，不等于任务完成位。** BOOT 按 `11005「極秘依頼　眠鳥を狩れ！」` 和 `11201「極秘依頼　樹海の迅竜！」` 登记事件，检查区域后运行事件状态机；正常结束和跳过均进入 `0x088d014c`，由 `0x088d0190` 调用标志写入器。这条写入链没有检查任务完成位。
- 357 参与 `2124「死に至る眠り」` 的显示；358 参与 `2228「疾風の迅竜」` 和 `2229「闇より生まれし者」` 的显示。中文说明采用原生事件语义，不能统一简化成“完成前置任务”。

此次任务图鉴不包含根据实时存档判断是否可接或修改解锁状态；若以后增加这些功能，需独立验证完整菜单、位阶与存档状态的组合行为。

## 奖励、支给品、怪物

- 全资源共 848 组、5,321 条奖励；菜单任务共 **747 组、4,917 条**，每组权重和均为 100。条目结构由结算代码确认。
- 菜单任务有 **7,470 条支给品配置**。奖励和支给品的道具 ID 均可关联当前 P2G 道具库，使用 `itemId`，不套用其他版本的 `saveId`。
- 747 组标志均已归入处理分支：基本抽选、无额外触发条件的单次抽选、指定大型怪物家族讨伐追加、训练用时、寻宝积分。总输出有 16 格上限，必须保留组顺序。
- 训练用时为严格小于门槛，多个时间组只取首个命中组。寻宝的 7 × 14 门槛已读出；原生算式明确对应 `questId - 4001` 和 `groupFlag - 268`，共 **98 组**，不是按文件顺序猜。
- `0x8000` 基本组在抽选序号 0 固定选择首个正权重条目；菜单任务有 443 组。82 条能严格交叉验证的 Wiki「確」记录，道具和数量均吻合。固定首抽与后续抽选权重须分别保存。
- **21016「ヒプノック討伐訓練」正常成功结算保证首项 `899 黑带硬币G ×1`。** 虽然任务文件的最低抽选参数为 0，但 DATA 53 的训练菜单经选中 ID、装备选择和开始入口设置模式位 `0x4`；任务初始化及结束保留该位。结算据此选用四次基本抽选表，首抽固定命中首项。443 个基本组均位于组序号 0，不会被前面的组耗尽 16 格上限；因此 443 组的首项保证均已闭合，保证语境为正常成功结算。
- 普通基本组默认后续继续阈值是 22/32，技能和模式会改变次数。每次抽选权重不等于整场获得率，本轮不生成未经验证的整场概率。
- 菜单任务有 540 条大型配置，涉及 ID 均可关联当前怪物库。551 个资源的小型配置全部读通，保留组、区域、共享指针和原始参数；实际小型怪物涉及的 23 个 ID 全部可关联。
- 小型实体表还含 `29 イワ`（岩石）。依据原生日文和既有排除表，将其保留为场景实体，不加入怪物关联。一张加载表恰好填满四槽，没有终止符，已按相邻节边界与引用核实并修正解析器。
- 任务目标、配置怪物、Wiki“主要怪物”分别保存；出场规则按下面的原生分组和条件表达，不能将所有组相加作为同时出场头数。

## 怪物分组与出场条件

- **大型怪物多组配置已有明确顺序语义。** `0x0886db04` 读取各组，`0x0886a4c4` 按组内序号分别追加到两个运行槽的队列；怪物清理路径经 `0x0886a604` 推进对应槽，再由 `0x0886a640` 装入下一项。450 个菜单任务中，29 个任务含多组大型配置，且每组恰好一项，均可表达为单槽依次出场。
- **小型怪物有三组，初始使用第 0 组。** 任务头 `+40 / +48` 是两条 8 字节切组规则，不是资源指针；它们分别推进到第 1／2 组。62 个任务共 67 条规则，其中 47 条按指定怪物讨伐事件计数，20 条检查当前携带道具数量。
- 讨伐计数先递减，至不大于 0 时触发；初始值为 0 也需一次事件。捕获另走处理路径，不能计入这项讨伐触发条件。道具条件调用 24 槽携带栏查询，不是交纳次数；所涉道具为蛋、结晶原石、火药岩等。
- 切组只向更大的组号推进，触发后锁存；两个计数从任务初始化时起独立累计。450 个菜单任务的脚本均未使用直接切组操作码 32。共享配置指针与分组身份继续保留，避免把替代组累计成同场数量。
- **同组两个运行槽也不能直接解释为同时出场。** `10510「最後の招待状」` 和 `3213` 的两只金狮子分别带原生变体参数 0／1；第二只进入专门等待状态。`10510` 先等待介绍事件结束，然后检查前一只的结束状态，或等待 18000 个游戏计时单位（按 30 tick/s 约 10 分钟）；`3213` 使用同类等待逻辑但跳过该介绍事件门槛。原生控制权门槛也保留，不能把约 10 分钟表述为任意运行状态下的精确墙钟时间。
- 新提取结果保留尚未解释的原始参数。本轮不将未知字段命名当作语义证据，也不声称复刻全部怪物 AI 或逐帧出场过程。

## 已明确的实施方式

1. 本体使用原生身份，Wiki 配信使用来源身份，保留完整性状态。先构建候选数据并审计关系，再接 UI。
2. 以 P2G 日文及上下文定名，优先经核对的 GU 官汉。317 个不同本体标题有 78 个 GU 日文同名候选；中文校对尚未完成，不能搬用 GU 任务数值和关系。
3. 任务 ↔ 道具、任务 ↔ 怪物、前置 ↔ 后续都使用稳定端点。既有怪物 Wiki 出没记录和道具旧任务记录须迁移到新身份，不能靠同名跳转。
4. 共享接口增加 P2G 身份和筛选适配；奖励使用 `itemId`，数量、概率、保证状态支持空值。Wiki 缺数字不是 0，未解析不是“没有奖励”。
5. 复用既有任务列表、详情、奖励和一级关联抽屉。沿用 `SearchableSelect`、水平紧凑筛选、正文先开抽屉及抽屉内关闭后定位的规则。
6. 验收静态目录、来源明确的条件与关系；不把未解释参数用于存档自动可接判断、精确出场模拟或整场概率计算。

UI 和既有道具／怪物图标没有资源前置阻碍。下一步是数据构建与中文校对、查询适配、页面及关系迁移、回归验收。本轮尚未建立实施计划或开始页面开发。
