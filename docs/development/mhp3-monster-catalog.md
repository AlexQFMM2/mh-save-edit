# P3 怪物图鉴：来源、构建与恢复

本地图鉴默认展示原生游戏图鉴的 60 条记录（40 大型、20 小型），扩展筛选另含 35、37、38、39、68 五个独立身份。NPC、岩石不进入目录。同名飞甲虫、垂皮龙及大小型狗龙不合并；名称、图标和对象编号不互相代替。

资料、译文、数据库、原生 PNG 和审计仅限本地。源码、构建器、合成测试与本文可以随代码维护，本轮未授权提交或公开发行 P3 运行资产。实施与验收记录见[交接](../../plan/mhp3-monster-catalog/handoff.md)。

## 来源与覆盖

原始候选中的 40 行愤怒倍率属于表尾战斗补充，不计入出没任务。构建器已拒绝含这些空任务名的 v1 产物；失败记录保留，不能安装。

保留的边界：

- 雷狼龙超带电尾尖射击肉质为 `null`。资料记载 15，原生两组数组为 10／15，但已定位状态切换未覆盖此行，不能强行闭合。土砂龙泥层条件按部位表达。
- 岚龙、霸龙、崩龙、煌黑龙的异常参考值包含资料指定的任务倍率；不反算成未经验证的基础值。毒伤害保留间隔；未注明单位的伤害不冒充总伤害。
- 陷阱／控制的通常、疲劳、愤怒及重复使用时间分别保存。未知和明确无效分开；条件免疫不简化成无条件有效。
- 每次数量、尝试次数、概率、原始权重独立。未注明每次数量保持未知，原生四字节采集字段不因位置相邻就提升为数量。村★2特例、普通下位／上位、捕获、破坏、剥取和背部采集保留各自路线。
- 飞甲虫 36～39 羽色按各自原生 slot 0、多个 rankCode 的完整道具／权重集合与独立资料绑定；49／68 垂皮龙池分别读取。相同掉落不合并身份。37～39／68 未绑定肉质、异常与出没，不借用正常条目。
- 小型怪物逐任务出没尚未收录。明确“无奖励”的路线单列；空数组不表示已经证明不存在。任务名称当前保留本作日文。

## 库、接口与关联

从当前完整武器版 `mhp3.sqlite` 副本追加 `p3_monsters`、`p3_monster_drops`。前者保留目录、固定详情与出没 JSON；后者按独立路线存储掉落，外键引用已有 `catalog_items.item_id`。双向查询都读取同一掉落表，不维护第二份道具来源数据。

`meta.monster_schema=mhp3-monsters-v1`，`monster_data_version` 为审阅输入 SHA-256。既有业务表、能力版本和其他五份数据库保持不变；本次没有改变道具身份绑定，不重建词典。

`MonsterCatalogGameId` 允许 `mhp3`，通用 `CatalogGameId` 和任务领域不变。身份为 `{ gameId: 'mhp3', monsterId }`；schema 拒绝越界、混合和跨作身份。`searchMonsters`、`getMonster`、`getMonsterFacets` 通过原有 preload 白名单和 IPC 转入独立只读 repository。旧库缺怪物模块时明确提示安装，已有图鉴继续工作。

默认范围 `normal`，另有 `extended`／`all`；关联 `targetMonsterId` 可越过列表筛选定位扩展身份。搜索支持中文、日文、别名、十进制／十六进制编号、掉落道具和出没任务；关系命中给出原因。道具来源筛选、详情和怪物名反查复用掉落表。

## 页面行为

复用共享 `MonsterCatalogPage` 和四个详情标签。P3 增加范围下拉、原文／译名来源／覆盖说明，以及条件和单位。未知肉质显示“未知”；未知状态不回退“通常”，未知耐性不冒充“不适用”。道具反查同样展示取得方式、位阶与次数。

选择、标签和筛选使用 URL；自动选中首条替换当前历史，用户选择新增历史。单纯选择不重新查询列表。正文关联打开一级抽屉，抽屉内关联关闭后定位；Escape 关闭并恢复触发焦点。

出没正文打开 P3 观察预览。从怪物抽屉点击出没，关闭后定位怪物页的 `appearance` 来源行；没有 P3 任务路由或服务。加载、读取失败重试、空搜索、目标不存在与未收录分别展示。

## 离线构建与审计

输入 `mhp3-monsters-input-v1` 保存基库／原生程序哈希、审阅状态、65 身份、全部详情／关系及图标绑定。输出必须为新私有目录：

```bash
python3 -B tools/mhp3/build_monsters.py \
  /path/to/complete-base/mhp3.sqlite \
  /path/to/frozen/catalog-input.json \
  /path/to/frozen/icons \
  /path/to/new-private-delivery
python3 -B tools/mhp3/audit_monsters.py \
  /path/to/complete-base/mhp3.sqlite \
  /path/to/frozen/catalog-input.json \
  /path/to/new-private-delivery
```

构建验证目录、中文／原文绑定、未知值、来源、关系端点、图标哈希与尺寸、完整性和外键，以及原业务表与 metadata。独立审计再次对比完整源／输出数据和关系。失败有 `FAILED.txt` 且无成功 manifest；不能安装。只有成功 manifest 与独立审计均通过的产物可进入本地安装。

公开测试均为合成数据：

```bash
python3 -B -m unittest discover -s tests -p 'test_mhp3_monsters.py'
pnpm typecheck
pnpm exec vitest run --exclude '**/.runtime-assets/**' --minWorkers=1 --maxWorkers=2
pnpm build
```

真实库的 Electron preload／IPC、1440×900 与 1024×768 截图和审计放私有研究区。Linux Electron 验证不代表 Windows 实包或游戏验收；实际执行结果以专题交接为准。

## 本地安装与恢复

先退出使用目标库的应用并关闭 SQLite 连接，不强制关闭用户未保存会话。验证候选 manifest、audit、数据库及 PNG 哈希；备份当前完整库后，将候选复制到 `data/` 的临时文件并原子替换 `mhp3.sqlite`。新增 PNG 复制到忽略的 `ui/public/assets/catalog/icons/`，同哈希文件内容必须一致，不删除任何现有图标。不替换词典。

重新构建／启动应用，验证正常／扩展目录、原五类 P3 图鉴、关系和其他五库哈希。若失败，退出应用后将安装前的完整备份原子恢复为 `data/mhp3.sqlite`，再启动验证。新哈希图标可以保留，避免删除其他模块共享图片。实际安装备份、库哈希与报告位置记录在[交接](../../plan/mhp3-monster-catalog/handoff.md)。
