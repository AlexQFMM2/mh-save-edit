# P2G 只读防具图鉴

复用 MH3G、MH4G、MHGU 的防具列表、套装矩阵、筛选和详情组件，提供道具、技能与防具关联。前期页面对照见[防具前置核查](../../plan/archive/2026-10-24/mhp2g-records/armor-preflight.md)，防具阶段固定基线见[装备交接](../../plan/archive/2026-10-24/mhp2g-records/equipment-handoff.md)。

后续 [P2G 配装器](loadout.md)和[存档编辑](save-editor.md)均已接入；当前状态见[整体验收](../../plan/archive/2026-10-24/mhp2g-records/acceptance.md)。本页保留防具图鉴的数据证据与阶段记录。

2,096 条原生记录中排除 5 条「装備無し」占位及 10 件训练专用耳饰 `armor_head:240`～`:249`。4 件奖励为剑圣、增弹、渴望、鹰眼耳环，展示取得条件；制作费用为空，不伪造配方。奖励条件分别来自特别训练全武器、斗技训练全武器、G 级训练全武器及村 9★「モンスターハンター」。

身份固定为 `armor_<head|chest|arms|waist|legs>:<index>`。`nativeIndex` 只在对应部位中有意义，不构造 Dex ID 或存档编码。P2G 没有护石；后续已接入共享“加入装备箱”入口及独立配装页，不提供幻化。

五部位原生记录为 40 字节。适用性取偏移 4 的低两位（性别）及后两位（剑士／射手），稀有度取偏移 5 加 1；防御、耐性、孔位、带符号技能点逐项核对。制作价格按本作制作菜单解释为原始价格的一半，只对有配方的防具显示。

最大防御按本作 getter 计算：基础防御加 `2 × clamp(max(偏移 20…26) − 1, 0, 63)`。最后一档受内部进度值 14 的检查约束；**没有证明它等于 HR14**。图鉴展示最终最大防御，与其他三作页面范围一致；不声称已完成逐级强化材料或全部进度解锁解释。

## 来源与审阅

数值、技能点和材料以干净日版原生表为准。日版 BOOT、五部位原生表与既有研究快照的哈希相同；名称绑定来自核实过的日文文本键，旧汉化只作为搜索别名。GU 只用于已有的逐条官汉名称对应，不复制后作数值或机制。

独立交叉证据采用历史 P2G 日文 Wiki 镜像，定向保存 407 个详情页面及来源日期、URL、哈希。套装依据页面明确成员和系列标题建立审阅映射，男女变体分别处理；不按原生相邻行或名称前缀猜分组。原生索引只用于分组后的默认展示排序。索引页首轮 35 处数值差异、详情页 78 行材料／技能差异及 23 处来源拼写修正均保留审阅记录，没有静默用 Wiki 覆盖原生数据。

奖励目录有独立训练资料与耳饰详情交叉支持；鹰眼耳环另已定位原生授予调用。其余三件训练奖励尚未完整追踪全部授予分支，不把当前证据描述为完整程序反编译。数值、身份、配方和已展示取得条件均有可追溯来源。

正式私有输入为 `../research/mhp2g/armor-catalog-v1/`，其中：

- `manifest.json` 固定原生表、配方、译名、套装、图标、正常目录输入及审阅来源；SHA-256 为 `85e17bd075d62a18de7321d3c1125998005a939e49cccc9080db0b6f5108b0f3`。
- `name-review.json` 保存新增 834 条中文名、日文、文本键、原生行哈希与依据；不改写旧 `localization-v4`。
- `sets-review.json`、`members-review.json`、`eligibility.json` 和 `dispute-decisions.json` 保存分组、身份、排除理由和差异判断。
- `wiki-sets/`、`native/` 保存最小来源观察；`source-manifest.json` 记录本次归档。图标与首轮证据沿用 `../research/mhp2g/armor-preflight-v1/`。

构建器重新解码原生防具记录并比对每个带符号技能点；逐条验证 26 字节配方行的哈希、目标部位／索引、材料编号和数量，再关联已有道具。输入、名称绑定、端点、图标或分组不一致时终止构建。

## 查询与界面

[独立查询仓库](../../api/catalog/p2gArmorRepository.ts)通过已有防具 IPC 通道分派，使用严格的 P2G 身份契约。新增六张 `p2g_armor*` 表，不改写旧技能／道具关系表；技能查询在安装防具库后覆盖正常目录名称、图标和配方，排除训练专用记录。旧的 7,180 条原生防具技能点仍保存在研究基线表中，正常页面使用其中 7,166 条。

默认套装视图，支持单件列表、分页、名称／原生键搜索、技能／材料反查和命中原因。筛选支持部位、职业、性别、稀有度、孔位和技能；排序包括防御、耐性、孔位和技能点。保留中文、日文和旧称搜索；下拉沿用可搜索组件和水平标签布局。

选择套装成员或列表条目只请求详情，晚返回的旧请求不能覆盖新选择。URL 可刷新恢复，兼容技能页旧 `equipment=armor_<part>:<index>` 参数。单件详情保留替代配方分组、名称来源、正负技能点、基础／最大防御、五耐性和取得方式。

正文点击材料或技能打开唯一一级抽屉；道具和技能正文点击防具打开完整防具抽屉。抽屉内再次点击关联对象，先关闭再导航定位。负技能点同样可点击，Escape 关闭后归还焦点；不嵌套抽屉。窄窗口采用上下布局并保留详情滚动区。

## 重建与安装

从仓库根目录运行，输出目录必须不存在。追加基线必须是**未含防具表**的完整武器／笛谱 v3；已安装的防具库不能再次作为这个构建器的基线。

```bash
node tools/build_mhp2g_armor_catalog.mjs \
  --base ../research/generated/mh-save-edit/mhp2g/catalog-weapons-v3/mhp2g.sqlite \
  --base-sha256 618d159340a162eeb843e66cfcca53a114c38a66e0c4c7b8402cd68d8bffbe7c \
  --review ../research/mhp2g/armor-catalog-v1 \
  --output /private/new-armor-catalog
```

构建器校验 SQLite 完整性、外键、正常目录计数、全部套装覆盖、替代配方和旧用途映射；原有 27 张业务表指纹必须保持一致。输出含完整数据库、40 张新增图标及 manifest；旧图鉴的图标继续使用已有资产。

正式交付：`../research/generated/mh-save-edit/mhp2g/catalog-armor-v1/`。数据库已原子安装到 `data/mhp2g.sqlite`，图标已按内容哈希安装到本地忽略目录。安装库 SHA-256：

```text
f26938db8b0125cb57aece86dbd6e6caa36de55a6e086ba6fafd6050a2bc14ad
```

验收与安装记录：`../research/generated/mh-save-edit/mhp2g/armor-verification-v1/`；其中 `pre-install/mhp2g-original.sqlite` 是安装前完整武器／笛谱 v3，哈希为上面构建命令的基线哈希。未覆盖前序备份，另外三作数据库哈希不变。未关闭用户应用；重启开发应用后刷新主进程只读缓存。回退时先退出应用、核对备份哈希，再复制到同目录临时文件并原子替换运行库。
