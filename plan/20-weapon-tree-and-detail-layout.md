# 武器派生视图与详情布局优化计划

状态：已实现，待真实窗口回归验收
计划日期：2026-09-13
范围：武器图鉴派生视图、武器节点卡片、右侧武器详情；与技能抽屉顶部发动效果布局联动验收

## 1. 当前问题

### 技能详情抽屉顶部发动效果

- 当前 `SkillActivationTable` 使用固定 `min-width: 840px`，在约 540～620px 的详情抽屉中必然出现横向滚动。
- 中文、英文、日文、说明和复合效果被挤在同一横向表格中，信息优先级不清晰。

### 武器派生视图

- `layoutWeaponTree` 使用固定行距，但没有把节点卡片的实际内容高度纳入碰撞计算。
- 节点卡包含名称、属性、孔位、斩味、生产/最终状态，真实高度可能超过布局使用的行距，因此同一列的卡片看起来堆叠或贴合。
- 派生树本身已经展示上下游关系，右侧详情底部再次显示“派生路线”，造成重复和视觉拥挤。
- 详情区、派生路线区和制作材料区在窄宽度下竞争垂直空间，右下角关系卡容易被压缩。

## 2. 布局目标

```text
武器图鉴
├─ 搜索与筛选工具栏
├─ 主工作区
│  ├─ 列表模式：武器列表  + 右侧完整详情
│  └─ 派生模式：派生画布   + 右侧核心详情
└─ 动作值模式：保持现有独立表格布局
```

派生模式的右侧详情只承担“当前节点资料”，派生关系由左侧画布承担；不再在右侧重复堆叠路线关系。

## 3. 技能抽屉顶部发动效果布局

本部分只针对技能详情抽屉内部的“发动效果”区域，不改变外部技能图鉴页面。

### 3.1 目标结构

```text
┌──────────────────────────────┐
│ 发动效果                  2   │
├──────────────────────────────┤
│ +10  正面                     │
│ 弱点特效                      │
│ Weakness Exploit              │
│ 弱点特効                      │
│ 中文说明……                   │
│ 英文说明……                   │
│ 复合效果：组件 A、组件 B      │
├──────────────────────────────┤
│ -10  负面                     │
│ ……                           │
└──────────────────────────────┘
```

### 3.2 具体规则

- 每条发动效果渲染为一个纵向效果卡，不再使用固定最小宽度的横向表格。
- 第一行只放阈值和方向，阈值保留正负符号，方向保留“正面/负面/特殊”文字。
- 发动技能中文名独占一行；英文名和日文名各自独占一行，可自然换行。
- 说明按中文、英文、日文纵向排列；缺失语言不生成空列。
- 复合效果改为可换行的组件列表，不挤占其他字段。
- 卡片内部不设置 `min-width`，抽屉内容区只保留一个纵向滚动所有者。
- 正负颜色仅作为辅助，文字和符号始终存在。

## 4. 派生节点卡片防重叠

### 4.1 布局算法

- 为节点定义统一布局契约：节点宽度、最小高度、列间距、行间距由 `WeaponTreeCanvas` 和 `layoutWeaponTree` 共享常量提供。
- 行距不再使用小于节点最小高度的固定值；最低要求为 `nodeMinHeight + rowGap`。
- 同一深度列按稳定顺序排列，并对每个节点执行碰撞修正：当前节点的 `y` 不得小于上一个节点的 `bottom + rowGap`。
- 共享子节点、多个根节点和深分支继续使用稳定排序；碰撞修正不能改变父子深度，只能增加纵向空间。
- 节点内容允许名称换行到最多两行，属性/孔位和斩味区域保持固定顺序；不通过 `overflow:hidden` 裁掉关键数据。
- 节点宽度不足时，优先增加画布可平移范围，不压缩到不可读尺寸。

### 4.2 画布交互

- 节点之间保持可见空隙，连线不得穿过节点内容。
- 选中节点居中时使用节点实际测量尺寸，而不是固定 230×108 假设。
- 保留缩放、平移、键盘方向导航和 minimap；不新增页面级滚动条。
- 派生树很大时允许画布内部平移/缩放，但节点卡片本身不产生横向滚动。
- `prefers-reduced-motion` 下取消居中动画，布局结果保持一致。

### 4.3 节点卡片视觉

- 卡片采用统一内边距和间距，标题、元数据、属性/孔位、斩味、徽标分区明确。
- 生产和最终状态徽标固定在卡片底部，不参与标题行挤压。
- 卡片 hover、匹配、选中、弱化状态继续使用文字/边框/透明度组合，不能只靠颜色。
- 卡片内容高度变化不能导致相邻节点重叠；长名称必须有稳定的两行高度契约。

## 5. 右侧武器详情与派生路线

### 处理结果

- 列表模式和派生模式均移除右侧详情底部的“派生路线”区块。用户需要查看上下游关系时统一切换到“派生”视图，避免两种模式出现两套不同的关系入口。
- 通过 `WeaponDetailPanel` 的显式 `showRelations` 属性控制，而不是页面 CSS 隐藏子组件。
- 右侧详情的顺序固定为：

```text
标题与身份
→ 核心属性
→ 斩味与瓶/炮击等专项参数
→ 制作方式与材料
→ （仅列表模式）派生路线
→ 底部图鉴写入操作
```

- 派生模式下右侧详情内容允许完整纵向滚动，但不再出现“详情内部滚动 + 派生路线卡片压缩”的双重拥挤。
- 如果后续需要从右侧跳转关系，使用派生画布上的父子节点或顶部“定位上下游”操作，不恢复重复路线卡片。

## 6. 响应式规则

| 宽度 | 发动效果 | 派生节点 | 右侧详情 |
| --- | --- | --- | --- |
| ≥ 1280px | 效果卡单列，字段完整换行 | 固定节点宽度，充足列/行间距 | 保留核心详情，派生模式隐藏路线 |
| 1024～1279px | 效果卡单列，英文/日文可换行 | 增加画布平移空间，不缩小节点到不可读 | 详情列保持最小宽度，内部纵向滚动 |
| 760～1023px | 效果卡字段堆叠 | 主工作区转为上下布局或保持画布最小高度 | 详情位于画布下方，路线仍隐藏 |
| < 760px | 效果卡所有字段纵向排列 | 画布独立高度 + 平移缩放 | 详情单独区域，不允许窗口整体滚动 |

禁止：

- 禁止发动效果表和派生关系使用固定 `min-width` 产生横向滚动。
- 禁止通过 `overflow:hidden` 裁掉节点名称、斩味或关系内容。
- 禁止在派生模式右侧重复显示完整派生路线卡片。
- 禁止用页面级选择器修改 `WeaponTreeNode` 内部布局。

## 7. 组件调整边界

### 需要调整

- `SkillActivationTable`：效果卡布局，取消横向滚动。
- `WeaponTreeCanvas`：节点尺寸契约、实际尺寸居中和画布边界。
- `weaponTreeLayout`：加入节点高度和碰撞修正，保持稳定排序。
- `WeaponTreeNode`：固定内容分区、长名称换行和底部徽标布局。
- `WeaponDetailPanel`：新增显式 `showRelations`，保持详情顺序和单一滚动区。
- `WeaponCatalogPage`：列表模式和派生模式均传入 `showRelations={false}`；其他复用场景保持默认兼容行为。
- `WeaponRelationList`：仅保留列表模式使用，统一关系行间距。

### 不调整

- 不改武器数据、派生关系、斩味数值或 Repository/IPC。
- 不改变列表模式的派生关系语义。
- 不移除动作值模式、派生画布缩放、键盘导航和 minimap。

## 8. 验收清单

- [x] 一条发动效果只占一个纵向效果卡，三语名称和说明完整可读。
- [x] 派生树同一列节点不重叠，节点之间保留稳定间距。
- [ ] 长名称、属性、孔位、斩味和状态徽标不被裁切。
- [ ] 选中节点居中使用实际尺寸，缩放和平移后仍可定位。
- [x] 派生模式右侧不再显示重复“派生路线”区块。
- [x] 列表模式同样不显示重复路线，统一通过派生视图查看。
- [ ] 1024/1280/1440px 下页面不出现窗口整体滚动。
- [ ] 键盘方向导航、焦点环、reduced-motion 和 minimap 保持正常。

## 9. 实施顺序

1. 先改发动效果卡，验证技能抽屉单一纵向滚动。
2. 冻结节点尺寸契约，修正派生布局的纵向碰撞。
3. 调整节点卡片内部内容分区和长名称处理。
4. 给武器详情增加显式 `showRelations`，派生模式隐藏重复路线。
5. 补充布局、技能抽屉、列表/派生模式和键盘交互测试。
6. 通过 `pnpm typecheck`、`pnpm test`、`pnpm build`、`git diff --check` 后再打包验收。
