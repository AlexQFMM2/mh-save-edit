## 目标与已确认决定

沿用 P2G 交付标准与现有共享怪物图鉴。默认 60 条游戏目录（40 大型、20 小型），另 5 条怪物／特殊对象通过扩展筛选可查；身份独立，NPC 和岩石不进入 UI。交付中文与原文、肉质、异常／控制、掉落、出没预览及怪物↔道具双向查询。

原生已验证语义优先；未解析字段可逐项采用本作独立资料并注明来源，仍无法确认则保留未知。雷狼龙争议状态不猜填，土砂龙保留逐部位泥层条件。概率、权重、每次数量、尝试次数分开。研究范围不扩大到完整任务图鉴、配装、存档或插件。

当前来源与未闭合项见[深入探查](../mhp3-investigation/monster-native-findings.md)。完整库基线为[武器交付](../mhp3-weapon-catalog/handoff.md)。研究和生成产物保持私有，构建与运行不连接宿主。

## 实施约定

在当前完整 P3 库副本追加 p3_monsters、p3_monster_drops 及独立版本，固定详情／出没采用 JSON；掉落引用现有 itemId。新增 MonsterCatalogGameId、P3 只读 repository，复用三条怪物通道；不扩通用 CatalogGameId，不重建词典。

复用共享页、主题与一级抽屉，P3 条件由专用数据／区域承接。出没采用独立来源键和预览抽屉，不调用未支持的任务服务。缺模块、未知、已核查无、加载失败分别处理。

任务、依赖和退出证据见[tasks.md](tasks.md)，状态见[taskList.md](taskList.md)，持续交接见[handoff.md](handoff.md)。后续波次以前序退出为条件，无工期承诺。

## 验收、安装与恢复

合成测试验证身份、未知值、状态条件、双向关系、旧库兼容和导航；真实资料检查全量端点、哈希、SQLite 完整性与外键，原有业务表与其他作品／词典指纹不变。完成类型检查、适当测试与构建，Vitest 排除 .runtime-assets。Electron 在 1440×900、1024×768 验收；Windows 实包与游戏验收单列。

仅安装带成功 manifest 的候选；关闭相关连接并备份后替换 P3 库及新增内容哈希 PNG。保留其他模块图片，不强制关闭未保存会话。失败恢复原 P3 库，其他数据库与词典不替换。
