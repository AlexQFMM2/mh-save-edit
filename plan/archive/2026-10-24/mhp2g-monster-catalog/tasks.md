# P2G 怪物图鉴任务

> 2026-10-24：本计划已归档；以下为原阶段任务与验收记录，当前结论见 [README](README.md#2026-10-24-归档结论)。

各任务负责人及最终整合负责人：项目维护者 / 当前接手开发者；仓库：`mh-save-edit`。采用串行执行，没有并行代理授权。所有任务共享 P2G 构建、身份类型和运行数据库，不同时写入这些资源。用户已明确要求实现，从 T-001 开始执行。

范围约束：只接入 P2G。3G、4G、GU 数据库与既有数据构建流程保持不变；已有资料只读参考。不重建 GU 术语快照，不开展全局怪物词典改造，不将三作同名记录的全面补核设为任何任务的依赖。

## B0：证据与身份

### T-001 核对日版来源、怪物名称与数据语义

- 输入：交接 README 列出的 r9、日版文本、原生怪物/奖励快照和 60 页 Wiki。
- 文件：新的 `tools/mhp2g/` 解析/审计模块及合成 fixture；真实映射和报告放私有 research 新目录。
- 输出：P2G 怪物/占位/变体名录，原生与 Wiki 显式对应，部位/模式/位阶/方法/单位的已确认项与缺口；干净日版相关窗口对照证据；P2G 专用日文与中文名称依据，不回写其他作或 GU 术语库。
- 执行顺序：先核对日版怪物/奖励来源窗口及原生身份，再用普通记录、同名变体和共享肉质数组的代表样本验证对应方法，最后覆盖其余 P2G 记录。只补核 P2G 所需的 GU 官汉用词；没有对应的结合日文上下文拟译，英文不主导身份匹配。
- 验收：不改旧快照和三作数据；错位、歧义与原文冲突被拒绝；同名原生记录不合并，未确认的变体标签不补写；雷/冰列和未知值保持正确；不借用其他作数值。未决字段明确保留，不伪造完整覆盖；已确认部分不依赖全局词典全面修复。
- 依赖：无。并行候选：否。交接：冻结输入清单、字段契约及通过的负向测试，供 T-002 / T-003 使用。

## B1：图标

### T-002 建立怪物图标来源与映射

- 输入：T-001 怪物身份及宿主机只读资源入口。
- 文件：独立怪物图标提取/审计模块；图片、atlas 元数据和哈希留私有 research。
- 输出：怪物 ID → 原生资源键 → 裁切/图标的显式映射、缺口说明。
- 验收：确认输入版本；逐项对应，缺失明确可见；不凭编号或名称相似度猜图；不复制完整纹理或包到 Linux。
- 依赖：T-001。并行候选：否。交接：图标覆盖与证据闭合后，方可开展对应 UI。

## B2：构建与接口

### T-003 生成怪物运行资料并接入查询

- 输入：T-001 字段和身份契约、T-002 图标映射、当前 P2G 道具库。
- 文件：`tools/mhp2g/`、构建/审计入口、独立怪物 repository、`api/catalog/{types,schemas,ipc}.ts`、preload 类型。
- 输出：可重复构建的 P2G 怪物表、查询/搜索/详情适配、真实怪物与道具关联；schema 的未知值与来源字段。
- 验收：数量/概率不被默认补值或重复换算；端点无悬空；原生编号与存档编号分离；缺库提示可恢复；独立适配 P2G，三作数据及既有构建流程不变、接口兼容；构建不依赖宿主机或网络。
- 依赖：T-001、T-002。并行候选：否。交接：公开合成测试和私有全量审计结果；不将生成库提交 Git。

## B3：页面与关联

### T-004 接入怪物页面、搜索和双向详情抽屉

- 输入：T-003 查询契约和已审计资料，现有怪物组件、道具详情抽屉。
- 文件：`ui/App.tsx`、怪物页面/组件、P2G 道具关系和相关类型；复用现有核心组件，按职责拆分。
- 输出：怪物列表、肉质/异常/掉落/已有任务资料；日中名称搜索；道具获取 ↔ 怪物掉落双向关联和 URL 定位。
- 验收：正文一级抽屉，抽屉内关闭后定位；不嵌套；不打开 P2G 存档/配装入口；页面无内部审校提示；未知数据不显示为 0 或虚构效果；复用三作现有模块时保持原有行为，共享改动限定于 P2G 接入所需兼容。
- 依赖：T-003。并行候选：否。交接：组件测试及独立 Electron 检查，保留用户原有会话。

## B4：整体核验与安装

### T-005 完成全量核验、备份安装与文档更新

- 输入：T-001～T-004 的代码、资料及验证记录。
- 文件：测试、运行核验工具、README、本计划及资料说明；报告和备份在忽略目录。
- 输出：可在本地查看的怪物图鉴、完整覆盖/缺口说明、可复现的构建与恢复步骤。
- 验收：类型/构建/相关和三作回归通过；逐条校验名称、ID、图标及关联；1366×768 和 3440×1440 可操作；安装前备份、失败可成套回滚；安装前后三作数据库哈希一致；无研究数据进入 Git。
- 依赖：T-004。并行候选：否。交接：记录实际验收结果后更新状态；GitHub 推送/Release 按后续用户指令执行，不由计划自动触发。
