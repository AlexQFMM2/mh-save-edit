## 目录边界与来源

原生武器表有 1,504 条记录，其中两个表首项是占位。其余 1,502 条不能直接全部认定为正常玩家目录：

- 1,501 条能从原生生产或锈块产物出发，经强化关系到达。
- 另有一条片手剑记录，未找到正常取得路径，独立日文目录也未收录。私有审计已将其隔离为 `quarantined-unconfirmed-acquisition`；不能擅自宣布它可取得，也不能从原始证据中删除。
- 图标提取覆盖全部 1,502 条非占位候选，供审计使用；这不改变上述收录边界。

身份始终使用原生表名与表内编号。此身份仅用于图鉴，不构成 P2G 存档装备编码的验证。

本轮使用日版 `D:\MH\unpack\mhp2gjp` 下的 BOOT、DATA 中指定 overlay 和单个 UI 纹理。宿主机全程只读；原始可执行文件、DATA、overlay 和图集未复制到开发机。仅返回限定指令片段、小表、哈希与裁切 PNG。独立交叉来源为已冻结的 P2G 日文 Wiki 镜像观察，不以其替代原生身份。

## 已确认的规则

| 内容 | 原生结论与实现约束 |
| --- | --- |
| 攻击显示 | 基础攻击乘本类显示系数，再整除 100。弩的改造与附件增量单独处理，不能混入裸武器基础值。 |
| 属性显示 | 普通属性与异常蓄积的显示值为原始值乘 10。双属性保留两侧及顺序，不能求和或覆盖。 |
| 斩味 | 累积模板按 `150 + 50 × steps` 截断；匠加 50，上限 450。原生负向修正减 50、下限 150；发现此机制不等于该技能属于正常可用目录。 |
| 会心 | 原始会心单独保留。战斗路径中，技能调整后的会心为正且属于近战时，当前蓝斩再加 5，白／紫斩再加 10。零或负会心不直接获得这项斩味补正。不要把 Wiki 的满斩有效会心写回原始字段。 |
| 弹药 | 原生可用掩码决定是否可装填，容量取模板；正容量不能证明武器支持该弹。装填数 UP 与追加弹种技能另算。 |
| 弓蓄力 | 原生上限 2／3／4 分别对应基础 2／3／4 段；装填数 UP 后为 3／4／4 段。不能把所有隐藏段都理解成第四段。 |
| 轻弩速射 | 独立武器编号表选择速射配置位；配置再给出弹种、连射数、伤害倍率及动作参数。已定位 82 把轻弩、100 个配置关联、22 组参数。不能把远程记录中全零的字段误认为速射掩码。 |
| 铳枪 | 专属编码取余 3 得炮击类型，整除 3 后加 1 得等级；弹仓容量另由类型决定。 |
| 狩猎笛 | 20 组原生音色三元组、47 条旋律匹配模式和 42 个效果分派编号已定位；须保留音符顺序及原生匹配约束。持续时间、重奏和技能修正尚未逐效果全部审计。 |
| 普通制作／强化 | 费用取目标武器原始价格整除 2。强化材料从目标的强化记录取得，不把源记录材料复制给每条出边。保留替代配方。 |
| 锈块／太古块 | 10 个伪目标配方不能作为武器 ID。已映射 30 个产物分支；制作费固定 1,000。原生按随机值模 100 的 `0..4`、`5..29`、`30..99` 区间选产物，不把区间宽度冒充已证明的精确概率。 |
| 制作可见性 | 已定位数量检查、四个材料标记字节、隐藏模式及内部进度阈值 14 的分支。阈值不是已证明的“HR14”；材料位图的写入来源及进度的玩家语义还需核对。末尾另一字段仍保留未知。 |

调用证据入口包括 BOOT `0x0881fc2c`（攻击显示）、`0x088dd3e8`（斩味）、`0x088dcf04`（会心）、`0x08822c3c`（弓蓄力）、`0x088da6b4`（弹药掩码）；game_task 的 `0x09b9f5e0`（速射）、`0x09bac338`（旋律）；lobby_task 的 `0x09a9eb98`（强化目标材料）、`0x09aa1540`／`0x09aa1568`（费用）、`0x09aa13a8`（锈块产物）。这些地址只适用于归档中哈希锁定的快照。

## 图标与复核

新增源码 [native_weapon_icons.py](../../../../tools/mhp2g/native_weapon_icons.py)，复用已验证的 [native_item_icons.py](../../../../tools/mhp2g/native_item_icons.py) 解码器。按原生模型到类别、类别到裁切描述符、稀有度到颜色的显式链路提取 24px 图标，共 88 个唯一 PNG。

武器绘制函数会将颜色表的字节 2、1、0 传给顶点 RGB；不能直接照搬道具的取色顺序。本轮已沿 `0x08831460 → 0x0882c360` 核对并修正，完成图标总览检查。图标及映射继续留在私有研究区，不复制到公开运行资产。

本轮验证结果：

- 固定快照的 1,504 条武器记录哈希与 pilot 一致；新读取的 1,502 条非占位图标映射与原生类别、稀有度及记录哈希一致。pilot 的完整性与外键检查通过。
- 独立资料中，1,478 把武器按类别及日文名称对应，攻击显示全部一致。比较只移除目录树装饰、空白和拉丁字母／数字宽度差异；不据此生成原生身份。其余观察保留未匹配状态。
- 95 把狩猎笛的音色顺序、87 把铳枪的类型与等级、132 条轻弩观察的速射弹种与发数全部一致；22 组速射参数的倍率、发数及资料反动分组也全部对应。
- 47 条原生旋律均找到独立资料的相同音符序列与效果名称；该结果不等于全部效果时长已原生验收。
- 958 条强化边均能找到目标材料，含 55 条跨武器类别的边及一组原生往返关系。遍历已采用防环方式，没有删除原生边。
- 价格、少数孔位／弹量／蓄力及一项会心仍与独立资料存在差异；逐项保留双方值。其中 7 项价格差异来自锈块费用口径，另有“不可用”显示为 `0` 或 `-` 的差别。不能为追求全部相等而修改原生数据。

研究验证脚本可从仓库根目录运行：归档中的 `validate.py`、`validate-specials.py`、`validate-eligibility.py`，按此顺序执行。脚本只读 pilot 和既有来源，将结果写回其所在私有目录；不更新运行 SQLite。图标提取器已在宿主机真实快照上执行，未运行与本轮无关的应用构建或 UI 测试。

## 接入顺序与剩余工作

已进一步对照三作实际页面，完整差距见[武器页功能对照](weapon-page-parity.md)。现有页面不展示长篇武器说明与制造解锁条件，两者不再作为当前页面接入前置；笛谱时长则属于现有详情能力，仍需补证。

1. **固定目录与数据构建器。** 以 1,501 条有取得路径的记录作为正常目录候选，保留一条未确认记录的隔离状态；从最新装饰品完整库的副本追加。将原始值、显示派生值、替代制作配方、目标强化材料及锈块分支分开表示。
2. **补齐页面需要的名称与专属详情。** 正常目录候选中 716 条已有 GU 用词对应，785 条尚无中文，可按既有约定先显示已核实日文；文本绑定不等于中文已验收。笛谱效果、时长及重复演奏语义须按本作补证，不套用后作重奏规则。长篇说明、材料位图写入、内部进度阈值和未知制造字段留作后续研究，不展示猜测的解锁条件。
3. **调整共享图鉴接口与派生组件。** 当前武器身份、查询及材料接口仍依赖三作 `GameId` 和必填存档字段，需要增加 P2G 图鉴身份入口。保留原生跨类边和回边，用跨类定位与防环布局呈现；不能裁掉关系来适配旧树形算法。
4. **复用现有武器列表、详情和一级关联抽屉。** 数据、可读名称、图标及关系端点闭合后再接 UI；适配最终形态筛选、替代配方与本作专属字段，保持其余三作行为。存档写入、配装和完整防具继续作为独立范围。

运行库基线仍是装备交接中 SHA-256 为 `439e769e…d6356` 的 `data/mhp2g.sqlite`。本轮未替换数据库、未提交、未推送，也未发布 P2G 数据或图标。
