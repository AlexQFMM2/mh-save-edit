## 归档前记录

状态：发动效果布局已实现；来源关系标签布局与点击闭环待后续实现
计划日期：2026-09-13
范围：技能详情一级引用抽屉内部、抽屉内发动效果和“相关防具 / 相关装饰品 / 相关护石”三个来源标签页

## 1. 目标

解决当前技能详情引用抽屉内部的三个主要问题：

1. 内容密度过高，防具/装饰品关系使用多列卡片，详情难以阅读。
2. 发动效果表在抽屉中被迫横向滚动，阅读体验差。
3. 抽屉内部的“相关装饰品”和“相关护石”标签页缺少可靠的可点击行为；关系条目需要整行可操作，并遵守一级抽屉规则。

本轮只冻结布局、交互和验收标准，不修改组件、Repository、IPC 或数据。

## 2. 参考图证据

### 已观察到（Observed）

- 参考图 1 的详情抽屉以“一个条目一行”为主，右侧详情按纵向分区排列。
- 参考图 1 的材料、技能和用途关系都是完整行按钮，图标、名称、数量/点数和状态在同一行内对齐。
- 参考图 2 的技能抽屉宽度有限，发动效果表被压缩后出现内部横向滚动。
- 当前实现的防具和装饰品关系使用多列网格；护石关系使用带 `min-width` 的表格，因此窄抽屉必然产生横向滚动。
- 当前 `SkillDetailPanel` 已经有技能头部、说明、发动效果、来源标签和关系列表五个结构层；本计划中的“来源标签”专指抽屉内部的三个标签页，不是外部技能图鉴页面导航。

### 布局推断（Inferred）

- 技能引用抽屉应采用固定宽度的单列阅读流，关系条目不再按四列或多列平铺。
- 发动效果适合改为“单条效果卡”，每条内部允许自然换行，而不是保留横向表格。
- 来源标签应保持三类始终存在；标签下的关系内容使用统一的单行卡片组件。
- 关系点击后必须先关闭当前抽屉，再跳转到目标图鉴或配装器，不允许第二层抽屉。

### 尚未知（Unknown）

- 用户最终使用的 Windows 缩放比例和最小窗口宽度尚未固定。
- 一条发动效果的最长三语说明和复合效果文本长度需要用真实数据库抽样确认。
- 护石点击后的最终落点是配装器护石选择器，还是直接打开技能预填条件，目前由配装器 URL 接口决定。

默认假设：抽屉可用宽度约 540～620px，最小可用宽度不低于 360px；长文本允许换行，不通过横向滚动解决。

## 3. 目标布局

```text
┌──────────────────────────────┐
│ 关联技能                  ×   │  ← DetailDrawer 公共头
├──────────────────────────────┤
│ 技能系 #ID · 0xID              │
│ 技能系名称                     │
│ English · 日本語               │
├──────────────────────────────┤
│ 技能系说明                     │  ← 可选，单列说明卡
├──────────────────────────────┤
│ 发动效果                  2    │
│ ┌──────────────────────────┐ │
│ │ +10 · 正面                 │ │
│ │ 弱点特效                   │ │
│ │ Weakness Exploit           │ │
│ │ 弱点特効                   │ │
│ │ 说明……                    │ │
│ │ 复合效果：……              │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ -10 · 负面                 │ │
│ │ ……                        │ │
│ └──────────────────────────┘ │
├──────────────────────────────┤
│ 相关防具  相关装饰品  相关护石 │  ← 三个等宽来源标签
├──────────────────────────────┤
│ 图标  名称/英文名        +2  2孔│  ← 一条关系一个按钮
│ 图标  名称/英文名        +1  1孔│
│ …                            │
└──────────────────────────────┘
```

### 3.1 抽屉外壳

- 继续复用公共 `DetailDrawer`，不创建第二套抽屉。
- 宽度使用组件变量，目标范围 `min(620px, 92vw)`；不改变正文宽度和页面滚动条。
- 抽屉内部只有一个纵向滚动所有者：详情内容区；来源关系不再创建横向滚动容器。
- 抽屉头部固定，关闭按钮、Escape、焦点锁定和焦点归还保持公共实现。
- 加载时保留旧详情内容，仅在内容区显示轻量更新状态，避免抽屉闪烁。

### 3.2 技能头部与说明

- 技能 ID、十六进制 ID、中文名、英文名、日文名保持现有信息顺序。
- 说明独占一行，长文本自然换行；不截断、不出现横向滚动。
- 说明缺失时显示统一空态文字，不改变区块高度契约。

### 3.3 发动效果区

- `SkillActivationTable` 不再使用横向表格作为主展示。
- 每条 `SkillActivation` 渲染为一个独立纵向效果卡，卡片之间使用统一 `gap`。
- 效果卡字段顺序固定：
  1. 阈值（带 `+/-` 符号）与方向文字。
  2. 发动技能中文名。
  3. 英文名和日文名，各自独立行，可换行。
  4. 三语说明按“中文优先、英文/日文辅助”纵向展示。
  5. 复合效果使用可换行的关系徽标/文本列表。
- 正面、负面、特殊只使用语义色辅助，同时保留“正面/负面/特殊”文字。
- 效果卡内部不设置 `min-width`，不允许横向滚动；超长名称和说明使用 `overflow-wrap:anywhere`。
- 效果数量较多时仍由抽屉主滚动区统一滚动，不嵌套第二个滚动条。

### 3.4 来源标签

- `SkillSourceTabs` 保留“相关防具 / 相关装饰品 / 相关护石”三项和数量。
- 三项在宽抽屉中等宽排列；窄于 480px 时允许标签文字换行或改为两行，不产生横向滚动。
- 发动效果区始终显示，切换来源标签只替换下方关系内容，不重复请求 `getSkill`。
- 标签支持鼠标、Enter/Space、左右方向键，当前选中项有文字和边框状态。

### 3.5 相关防具与相关装饰品

- 取消多列网格，改为单列关系列表；一条关系占一整行。
- 行结构统一为：图标｜中文名与英文名｜部位/孔位｜技能点数。
- 整行使用原生 `<button>`，点击图标、名称、孔位或点数均触发同一动作。
- 行内字段允许换行；名称区 `min-width: 0`，数量/点数区域固定靠右。
- 行间使用统一 `gap`，不使用依赖边框相邻关系的“贴合卡片”。
- 防具点击：关闭技能抽屉，跳转防具图鉴并携带 `target` 和选中项。
- 装饰品点击：关闭技能抽屉，跳转装饰品图鉴并携带 `target` 和选中项。
- 目标图鉴恢复后，详情请求应使用序号丢弃过期响应。

### 3.6 相关护石

- 取消 `min-width: 720px` 的横向表格，改为单列护石关系卡。
- 每张关系卡固定展示：
  - 护石品级。
  - A/B 技能位。
  - 技能系名称。
  - 合法点数范围。
  - 孔位上限或“未确认”。
  - `exact / rule / unknown` 来源状态。
- 宽抽屉内使用两行信息布局：第一行品级 + A/B + 范围，第二行孔位 + 来源；窄抽屉自动改为多行。
- 护石关系也使用整行按钮，点击区域覆盖整张卡。
- 点击后关闭技能抽屉，跳转配装器并携带：

```text
skill
talisman
position
range
```

- 配装器负责打开护石选择器并预填技能、技能位和合法范围；不在技能抽屉内嵌套护石选择器。
- 如果当前版本暂时无法定位配装器入口，关系卡显示只读来源状态并提供明确不可用原因，不能渲染无响应按钮。

## 4. 组件调整边界

### 需要调整的组件

- `SkillDetailDrawer`：只负责抽屉宽度变量和关系跳转闭环。
- `SkillDetailPanel`：负责单列详情流和 `onSelectTalisman` 回调。
- `SkillActivationTable`：从表格改为效果卡列表。
- `SkillArmorRelationList`：从多列网格改为单列关系按钮。
- `SkillDecorationRelationList`：从多列网格改为单列关系按钮。
- `SkillTalismanRelationList`：从横向表格改为单列关系按钮。
- `SkillSourceTabs`：保持三标签结构，只补窄宽换行和焦点契约。
- `SkillDetailDrawer` 及其内部 `SkillDetailPanel`：承载三个来源标签页的关系点击；点击后关闭当前抽屉，再由当前调用方跳转目标图鉴。
- `SkillCatalogPage`、`DecorationCatalogPage`、`ArmorCatalogPage`：只提供现有抽屉关闭后的目标落点和 URL 恢复，不改变页面自身布局或增加新的来源标签。
- `LoadoutBuilderPage`：接收技能/护石 URL 参数并在打开时预填护石选择器；若该入口尚未准备好，先提供明确的不可用状态。

### 不调整的边界

- 不修改技能数据库、阈值、护石范围和来源证据。
- 不改变 `getSkill` 一次返回完整详情的 IPC 约定。
- 不新增第二层 `DetailDrawer`。
- 不让来源标签切换重复读取详情。
- 不把护石关系误显示为已生成的护石实例。

## 5. 响应式和滚动契约

| 宽度 | 详情布局 | 关系布局 | 滚动规则 |
| --- | --- | --- | --- |
| ≥ 620px | 单列，标题/说明/效果/来源依次排列 | 一条关系一行，字段横向对齐 | 仅抽屉内容区纵向滚动 |
| 480～619px | 单列，三语内容自然换行 | 一条关系一行，名称区可换行 | 禁止横向滚动 |
| < 480px | 头部信息纵向堆叠 | 每条关系卡改为两行或三行 | 仅抽屉内容区纵向滚动 |

禁止事项：

- 禁止效果区、护石区出现第二个横向滚动条。
- 禁止父级 `overflow:hidden` 裁掉关系卡内容。
- 禁止使用固定 `min-width` 迫使抽屉变宽。
- 禁止通过颜色作为唯一点击/状态提示。

## 8. 实施顺序

1. 先建立单列详情骨架和抽屉滚动契约。
2. 将发动效果表改为无横向滚动的效果卡。
3. 将防具、装饰品、护石关系列表统一为单列关系按钮。
4. 补齐装饰品和护石的关系点击回调及一级跳转。
5. 接入配装器护石预填入口，保留版本/能力不可用时的明确反馈。
6. 补组件测试、键盘测试和三种窗口截图回归。
7. 通过 `pnpm typecheck`、`pnpm test`、`pnpm build` 和 `git diff --check` 后再推送 Windows 包。
