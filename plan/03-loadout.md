# 阶段 3：配装器与自动配装

当前状态：阶段 3A/3B 首版实现完成，正在处理自动搜索完整性审计；实施细节见 [12-loadout-builder.md](12-loadout-builder.md) 与 [14-loadout-builder-ui.md](14-loadout-builder-ui.md)（2026-09-13）。装备箱导入和一键写入已作为存档桥接接入，但不改变本计划的纯逻辑模型。

## 1. 核心模型

配装是逻辑方案，不是装备箱七个实例的别名：

```text
Loadout
├── contentGame
├── schemaVersion/dataVersion
├── name
├── hunter constraints
├── weapon definition + level + decorations
├── five armor definitions + levels + decorations
├── talisman grade + skills + slots + decorations
├── optional fixed instance parameters
└── local metadata
```

不保存装备箱格号、存档路径或角色槽。未来从装备箱导入时只读取：装备身份、等级、珠子、护石技能以及
发掘装备/猎虫确实需要的实例参数。

## 2. 手动配装器

默认从普通完整图鉴和 MH4G 配装专用发掘模板中选择装备，不要求用户装备箱中已经存在该实例。发掘模板只在配装器内出现，不改变普通武器/防具图鉴的排除规则。首版选择器实现图鉴与模板入口；装备箱来源留到阶段 2 桥接：

- “普通图鉴”：三作正常默认候选。
- “发掘模板”：仅 MH4G 手动配装可见；从模板创建独立 28 字节草稿，不修改共享模板。
- “当前装备箱”：后续存档编辑阶段的可选来源，不进入本轮实现或验收。

手动配装必须支持：

- 武器、头、胸、腕、腰、腿、护石七槽。
- 每个槽独立分配装饰珠。
- 性别、剑士/射手和各作职业限制。
- 实时计算孔位、防御、耐性、技能点、发动技能和冲突诊断。
- 撤销/重做、新建、复制、本地保存、JSON 导入导出。
- 装备/技能详情跳转到阶段 1 图鉴。

## 3. 计算器

计算器是纯函数模块，不依赖 React、Electron、SQLite 连接或当前存档：

```text
calculateLoadout(catalogSnapshot, loadout) → LoadoutResult
```

结果至少包含：

- 总防御和五耐性
- 各技能树总点数
- 已发动、未发动和负面技能
- 总孔位、已用孔位、剩余孔位和超孔诊断
- 性别/职业/等级/ID 合法性诊断
- 各游戏特有摘要

三作分别实现规则插件，共享汇总框架。不能用大量 `if (game === ...)` 散落在一个计算器中。

GU/XX 特殊技能的顺序已经冻结：护石强化先将护石技能贡献乘 2，秘术再对汇总技能系增加 2 点；受两者共同影响的值必须按 `x × 2 + 2` 计算，禁止实现为 `(x + 2) × 2`。胴系统复制仍先按胸部固有技能与胸部装饰珠的原始贡献独立计算，并在技能矩阵中保留可解释的特殊修正列。

## 4. 护石与特殊装备

- 护石是逻辑等级、孔位、两项技能和技能点，不依赖装备箱实例。
- 自动生成护石必须满足对应游戏已审计的自然范围。
- 手动固定的已有护石可以携带不自然值，但结果必须以状态文字、原因和警告样式明确提示并保留，不能只靠红色表达。
- MH4G 发掘武器/防具在本阶段即可从配装专用模板手动创建并高级编辑；完整实例必须保留 28 字节原始记录和字段级补丁。装备箱中的既有实例仍留到后续存档桥接导入。
- MH4G 旧修改器和当前解包不能证明发掘随机参数、护石技能/孔位组合的自然生成合法性；这些实例的字段可以结构化编辑和无损写回，但自然合法性固定显示为 `unknown`，不能在 UI 或自动搜索中伪装为 `confirmed`。
- 手动配装允许自然非法或证据不确定但结构可编码的发掘装备、护石和超孔珠；必须展示原因，不得自动修复。自然合法性与结构可编码性是两条独立状态轴，只有后者失败才阻断应用。
- 自动搜索不会生成发掘装备、非法护石以及无法确认自然生成参数的动态装备；用户明确固定且可计算、可编码的实例可以作为常量输入保留，求解器不得改写其身份、高级字段或已固定装饰珠。
- GU/XX 猎虫和猫装备不强行塞进猎人七槽配装模型，使用扩展模型单独处理。

## 5. 自动配装输入

```text
AutoLoadoutRequest
├── target skills and minimum levels
├── fixed equipment/talisman
├── weapon slot assumption or fixed weapon
├── hunter gender/combat type
├── allowed ranks/rarities
├── include/exclude IDs
├── result limit
└── ranking weights
```

`owned-only` 只是后续存档桥接阶段的可选筛选条件；本轮自动搜索始终使用完整图鉴候选。

## 6. 自动搜索实现

搜索在 Worker Thread 中运行，支持进度、取消和超时，不阻塞 Electron 主进程或 renderer。

建议顺序：

1. 根据性别、职业、固定件和排除条件预筛装备。
2. 将目标技能无贡献且属性不占优的装备做安全支配剪枝。
3. 按部位组合并维护技能上界、可用孔位和防御上界。
4. 搜索护石候选。
5. 用装饰珠解剩余技能点和孔位问题。
6. 对相同逻辑套装去重并按稳定规则排序。
7. 对最终候选调用正式计算器重新验证，不能信任搜索中间摘要。

排序默认依次考虑：满足目标、风险等级、剩余孔位、防御、耐性、额外发动技能和稳定 ID 顺序。用户
可改变权重，但相同输入和数据版本必须得到可重复结果。

## 7. 装饰珠求解

- 珠子占孔、正负技能点和胴系统等特殊规则由游戏插件提供。
- 珠子分配结果写回各装备槽，不生成独立顶层珠子池。
- 求解器必须处理负技能、副作用、不同占孔和多目标技能。
- “仅已有素材/珠子”属于后续存档桥接筛选，本轮不实现。

## 8. 后续加入装备箱（本轮不实现）

以下内容仅记录未来阶段 2 与阶段 3A 的桥接协议，不属于当前技能图鉴或纯配装器实现范围。

用户确认结果后才把逻辑配装物化为存档实例：

```text
逻辑配装
→ 游戏 adapter 验证可生成性
→ 生成七条临时实例
→ 检查目标装备箱空位
→ 在文档副本中一次写入
→ 正式计算并复核
→ 提交 dirty patches
```

这一操作不自动穿戴、不自动写磁盘。任意一条实例无法生成或装备箱容量不足时，七条都不写入。

## 9. 本地协议

`.mhloadout.json` 必须包含：

- 固定 schema 标识和版本。
- 游戏、数据版本和生成客户端版本。
- 七槽逻辑数据或确有必要的完整实例参数。
- 每件装备自己的装饰珠。

技能汇总、防御、合法性和在线点赞数不是权威字段。导入后始终用当前本地数据库重新计算。未知
schema 或不兼容 `data_version` 先提示，不静默改 ID。

## 10. 验收门槛

当前已完成：七槽逻辑配装、三作规则计算、护石/装珠自由编辑、合法性与结构编码双状态、MH4G 发掘模板高级编辑、单 Worker 自动配装队列、本地任务历史、一级工作抽屉与 JSON 导入导出。自动任务关闭抽屉后继续运行，重启时未完成任务转为可重跑的中断记录；历史结果应用前按当前资料重新复核。`pnpm typecheck`、最多 2 workers 的完整测试、`pnpm build` 和 `git diff --check` 均作为提交前门槛。

为修复“原游戏合法配装搜不到”增加独立的可重复验证入口规划：`pnpm loadout:verify`。它只接受严格的
游戏、技能/发动效果、阈值、武器和性别参数，调用正式的资料快照、规则插件、计算器和自动搜索，输出
技能 crosswalk、护石孔位处理、候选剪枝、装珠分配、七槽结果和正式复核状态。脚本与 UI 共用同一搜索
入口，不允许复制一套简化算法；具体输入/输出约定见 [12-loadout-builder.md](12-loadout-builder.md#131-可重复的自动配装验证脚本)。

当前阶段验收以纯图鉴候选、手动配装和自动计算为准；涉及装备箱的条目在后续存档桥接阶段验收。

- 未打开存档也可以完整使用手动和自动配装器。
- 从普通图鉴和 MH4G 配装专用发掘模板可以选择装备；不会被强制限制为装备箱实例。
- 从装备箱导入后删除/移动原格，不影响当前逻辑配装。
- MH4G 可从配装专用模板建立发掘武器/防具并编辑高级字段；非目标字节逐字节保留。
- 三作计算结果与旧实现和固定夹具一致。
- 自动搜索可取消、不会冻结窗口，相同输入输出顺序稳定。
- 每个自动结果经正式计算器复核后都满足目标。
- 动态装备不会被无依据自动合成。
- 一键加入在五种格式中保持原子性和未知字节安全。

## 11. 2026-09-13 自动搜索完整性审计结论

- MH3G、MH4G 的防具技能关系已逐条与技能表对齐，没有发现 MHGU 那种 Dex 技能树 ID 未经 crosswalk 直接写入的错位。
- MHGU/XX 仍存在确定性技能 ID 错位：Dex 技能树与原生技能 ID 不是同一命名空间，必须在构建器阶段完成显式映射后才能重新生成配装快照。
- MH4G/MHGU 的护石规则没有具体 `slot_count` 时，当前实现错误地按 0 孔进入自动搜索；这会漏掉依赖护石孔位的合法组合。
- 三作都仍有候选前 50、beam 800 和装饰珠贪心分配造成的完整性风险。旧修改器可证明规则和样本路径可迁移，但不能证明当前启发式搜索覆盖所有原游戏合法组合。
- 在上述问题修复并完成三作合法样本回归前，自动配装状态只能标记为“已找到满足条件的候选”，不能标记为“已穷举全部合法配装”。
