# 三作配装器 UI 与交互实施计划

状态：阶段 3A 页面、工作抽屉与自动化交互验收完成；图标、持久自动任务、历史管理、结果密度、滚动和首次加载均已闭环，等待阶段 3B 存档桥接（2026-09-10）

关联计划：[12-loadout-builder.md](12-loadout-builder.md)、[13-skill-catalog.md](13-skill-catalog.md)

## 1. 设计目标

配装器是高频编辑工具，不是图鉴详情页。首版必须让用户在一个页面内完成：

```text
选择武器与五件防具
→ 配置护石
→ 给每一件装备安装装饰珠
→ 实时查看技能、防御、耐性和孔位
→ 选择多个目标技能并自动搜索
→ 对比并应用结果
```

页面继续使用项目现有棕金主题、五档字号、亮金数据色、水平字段布局和内部滚动。用户未读取存档也能使用全部手动和自动配装能力；本轮模型只表示逻辑配装，不显示装备箱格号，也不触发存档 dirty。

本设计遵循以下原则：

- 装备表和实时计算结果始终同时可见，不用多步向导拆散手动配装。
- 选择器、护石和装珠都使用可撤销草稿，只有右侧工作抽屉底部的“应用”才修改当前配装。
- 自动配装中的“固定”必须有明确锁定状态，不能把“当前已选”偷偷等同于“必须保留”。
- 多技能目标选择的是具体发动效果与阈值，例如“弱点特效｜痛击 +10”，不是含义不明的“痛击”。
- 不使用拖拽作为唯一操作；添加、移除、锁定和排序都必须有原生按钮与键盘路径。
- 所有操作统一从右侧划出工作抽屉，使用 portal 和 `position: fixed`，打开时不得改变页面宽度、横向位置或主滚动容器。
- 手动编辑优先保证无损表达：自然非法、超孔或证据不确定不等于不能保存；真正不可编码时才阻断。

## 2. 页面总体结构

主页面不再采用左右 `40% / 60%` 分栏。参考 Dex 截图后固定为全宽三段式：顶部紧凑选装、中部装备属性表、底部技能矩阵。装备选择只需要较少高度，而两张数据表都需要完整横向空间。

```text
┌ 配装名称 | 性别 | 剑士/枪手状态 | 新建 | 导入 | 导出 | 自动配装 ┐
├──────────────────────────────────────────────────────────────────────────────┤
│ 七槽快捷选择：武器 / 头 / 胸 / 腕 / 腰 / 腿 / 护石                           │
│ 每行：部位图标 | 装备名称 | OOO | 已装珠摘要 | 装珠 | 固定 | 更换              │
├──────────────────────────────────────────────────────────────────────────────┤
│ 当前装备属性表：名称 | 职业 | OOO | 防御 | 最大 | 火 | 水 | 雷 | 冰 | 龙 | 合计 │
├──────────────────────────────────────────────────────────────────────────────┤
│ 技能系矩阵：技能系 | 武器 | 头 | 胸 | 腕 | 腰 | 腿 | 护石 | 修正 | 合计 | 发动 │
│                                                                              │
│ 诊断：剩余孔、临界技能、负面技能、职业/性别冲突、自然护石状态                 │
└──────────────────────────────────────────────────────────────────────────────┘
```

页面骨架：

- 顶部工具栏只放全局状态和操作，不放装备筛选。
- 顶部选装区采用 Dex 风格的紧凑表格式七行，不使用七张大卡；建议占内容高度约 30%。
- 中部属性表建议占约 24%，始终展示五件防具与合计；武器和护石没有防御/耐性时不制造空数据行。
- 底部技能矩阵获得剩余约 46% 高度并作为主要滚动区；属性与技能结果来自同一个不可变计算快照。
- 三段都横向撑满。属性表和技能矩阵各自拥有固定表头与低对比滚动条；窗口整体不滚动。
- 高度不足时优先压缩顶部行距，再让中部属性表进入内部滚动，不能隐藏技能矩阵或缩小全局字号。

### 2.1 七槽装备表

固定顺序：

```text
武器｜头｜胸｜腕｜腰｜腿｜护石
```

每行固定展示：

```text
部位图标｜名称与副名称｜稀有度/品级｜OOO 孔位占用｜已装珠摘要｜固定状态｜操作
```

- 点击“选择/更换”“装珠”“编辑”从右侧划出对应工作抽屉；行主体本身只负责选中，不触发模糊操作。
- `选择/更换`、`装珠`、`清空`、`固定`是独立按钮，不能让整行同时承担多个模糊动作。
- “固定装备”使用锁图标加“已固定/未固定”文字和 `aria-pressed`；该二态开关主要提供给自动配装，也可在主页面预先设置。是否连同珠子固定在自动条件中单独选择，不能把三种含义挤进一个看不懂的锁图标。
- 武器必须先确定近战/远程约束。更换武器导致现有防具不兼容时，显示逐项冲突并要求用户确认；不得静默清空防具。
- 更换某件装备时，该行原有珠子默认随旧装备保留在撤销快照中，但新装备从空珠状态开始。确认前明确提示将移除哪些珠子。
- 护石行显示品级、A/B 技能及有符号点数、OOO 和自然状态，不伪装成普通防具。

### 2.1.1 Dex 参考的紧凑选装区

Dex 截图顶部的“部位图标 + 名称 + `+` 按钮”作为快捷填充入口保留，但语义改为可读的原生控件：

```text
┌ 武器  [图标]  未选择/当前武器                         [+ 选择] ┐
│ 头部  [图标]  当前头部防具                             [+ 更换] │
│ 胸部  [图标]  当前胸部防具                             [+ 更换] │
│ 腕部  [图标]  当前腕部防具                             [+ 更换] │
│ 腰部  [图标]  当前腰部防具                             [+ 更换] │
│ 腿部  [图标]  当前腿部防具                             [+ 更换] │
│ 护石  [图标]  A 技能 / B 技能 / OOO                      [编辑] │
└──────────────────────────────────────────────────────────────┘
```

- `+` 不能单独承担“新增、替换、打开详情”多个含义；按钮旁始终显示“选择/更换”。
- 一行只代表一个存档逻辑槽位，部位图标用作定位辅助，名称和文本标签仍必须存在。
- 选择后在同一行显示 `OOO` 孔位、已装珠摘要和固定状态；不再像 Dex 一样只显示难以区分的图标按钮。
- “套装快捷填充”可以在头部工具栏提供，但填充后仍逐行展示并允许单件替换，不能把套装名当成七槽实体。

### 2.2 全宽实时结果

中部保留一张横向撑满的当前装备属性表，吸收 Dex 截图中“防具 / 防御 / 最大 / 五耐性 / 合计”的信息密度：

```text
部位｜防具名称｜职业｜OOO｜基础防御｜最大防御｜火｜水｜雷｜冰｜龙
头部｜……     ｜剑士｜OOO｜128       ｜136      ｜ 2｜-1｜ 0｜ 1｜-2
胸部｜……     ｜剑士｜OO-｜134       ｜142      ｜ 3｜ 0｜-2｜ 0｜-1
……
合计｜         ｜     ｜11 ｜612       ｜680      ｜ 8｜-4｜ 6｜ 2｜-8
```

- 总计行固定在表尾；符号、数据颜色和文字同时表达正负耐性。
- 该表只展示当前已选装备，不承担候选搜索；候选搜索统一进入 `EquipmentPickerDrawer`。
- 点击名称仍遵守图鉴正文的一级详情抽屉规则；工作抽屉内部只更新预览，不嵌套抽屉。

底部始终显示横向撑满的技能矩阵，按技能系为行，列固定为（参考 Dex 底部表格）：

```text
技能系｜武器｜头｜胸｜腕｜腰｜腿｜护石｜装饰珠修正｜特殊修正｜合计｜发动效果
```

胴系统复制和 GU/XX 特殊修正单列显示，不篡改原始装备贡献。每个单元格保留 `+/-` 符号；零值显示 `—`，不留空白造成“未计算”的误解。矩阵只在自身区域横向滚动，首列、合计列和发动效果列保持可见。点击技能系或发动效果时打开技能图鉴一级详情抽屉。

矩阵默认显示所有非零技能系，并允许切换“全部 / 已发动 / 临界 / 负面”。已发动负面效果使用符号、文字和警告图标共同表达；临界项显示“痛击 8/10，还差 2”。GU/XX 同时存在护石强化与秘术时在特殊修正列显示 `x × 2 + 2`，避免结果看起来像黑箱。

底部诊断条展示总孔位/已用/剩余、职业与性别合法性、自然护石状态和所有阻断原因。错误靠近对应装备行同步显示，不能只在底部给一条笼统错误。

## 3. 统一右侧工作抽屉

新增 `LoadoutWorkspaceDrawer` 作为选择装备、编辑护石、逐件装珠和自动配装的唯一操作壳层。它与图鉴详情抽屉共享 portal、焦点和遮罩基础能力，但内部宽度更大、支持工具视图状态，不复用只读详情面板。

- 通过 portal 渲染到应用根级 overlay，使用 `position: fixed; inset: 0`；抽屉从右侧覆盖页面，不参与正文 grid/flex 布局，因此主页面不得产生横向偏移。
- 打开时使用滚动锁定补偿保持正文几何尺寸；不得通过给正文增加 margin、缩窄 grid 或改变根容器宽度“腾出”抽屉空间。
- 1280px 以上建议宽度约为可用内容区的 62%～72%，最高不超过视口；1024px 使用约 78%～88%；更窄时覆盖整个内容区。
- 抽屉内部固定为“标题/返回路径 → 水平筛选 → 主列表/表单 → 预览或诊断 → 应用/取消底栏”，只有中间内容滚动。
- 打开后焦点进入搜索框或第一个表单控件；Tab 顺序与视觉顺序一致；Escape 放弃当前草稿并关闭；关闭后焦点归还触发按钮。
- 页面同时只维护一个活动工作抽屉。自动配装中需要更换装备时，在同一个抽屉内切换为选择器子视图并提供“返回自动条件”，严禁再打开第二层抽屉或 dialog。
- 抽屉内点击图鉴关联对象不再打开另一个详情抽屉；改为先关闭工作抽屉，再跳转对应图鉴并定位，遵守全项目一级抽屉规则。
- 列表单击只更新抽屉内预览；点击固定底栏的“应用选择/应用修改”才提交。切换子视图、关闭或取消都保留主页面原值。
- 抽屉子视图拥有自己的草稿检查点。存在未应用修改时点击返回、切换工具或关闭，显示“放弃修改 / 继续编辑”；已应用到抽屉主草稿但尚未提交七槽的修改仍可由最外层取消整体回滚。
- 自动搜索正在运行时关闭工作抽屉只收起界面，后台任务继续执行；只有明确点击“取消任务”才停止 Worker。工具栏持续显示活动任务数，并可从“历史任务”恢复进度与结果。

所有选择器共享：短延迟搜索、`SearchableSelect`、固定表头、分页或虚拟化、旧结果保留、请求序号、空/错/加载状态、重置筛选和键盘上下选择。

### 3.1 工作抽屉布局

装备选择时，正文保持原位，遮罩与抽屉覆盖在其上：

```text
┌────────────── 原配装页面（不位移） ──────────────┬──── 遮罩 + 右侧工作抽屉 ─────────────────────┐
│ 七槽 / 属性 / 技能矩阵保持尺寸与滚动位置          │ ← 返回路径       选择头部防具       关闭      │
│                                                   ├─────────────────────────────────────────────┤
│                                                   │ 关键词｜职业｜性别｜技能｜孔位｜排序｜重置 │
│                                                   ├───────────────────────┬─────────────────────┤
│                                                   │ 候选列表              │ 当前候选预览        │
│                                                   │ 图标 名称 OOO 技能值  │ 属性/技能/替换差值  │
│                                                   │ …内部滚动             │ …内部滚动           │
│                                                   ├───────────────────────┴─────────────────────┤
│                                                   │               取消｜应用选择               │
└───────────────────────────────────────────────────┴─────────────────────────────────────────────┘
```

- 候选列表获得主要宽度，预览只占足够阅读详情的次要宽度；窄抽屉改为“候选 / 预览”标签，不把两列压到不可读。
- 抽屉标题、筛选条和底部操作固定；列表与预览各自内部滚动，滚动条沿用项目低对比棕金样式。
- 护石和发掘高级编辑改用全宽表单；装饰珠使用“候选列表 + 当前槽位”；自动配装使用“条件 / 结果”顶层标签，均复用同一个外壳。
- 抽屉打开期间浏览器后退或游戏版本切换视为离开页面：取消 renderer 侧候选请求并丢弃未应用草稿，但已经提交给主进程的自动任务继续执行；页面通过游戏 ID、任务 ID 和请求序号隔离结果，不得把上一游戏的异步结果写入当前配装。

复用边界固定为“浏览核心组件”，不能把整个图鉴页面直接挂入抽屉。武器、防具、装饰品和技能浏览器至少提供统一选择协议：

```ts
type CatalogInteractionMode = 'browse' | 'select'

type CatalogSelectionProps<TIdentity> = {
  mode: CatalogInteractionMode
  selectedIdentity: TIdentity | null
  onSelectionChange(identity: TIdentity): void
  onConfirm?(identity: TIdentity): void
}
```

- 可复用：查询工具栏、筛选器、候选列表、列表行、分页、详情只读主体、图标和加载/空/错状态。
- 不复用：图鉴页面壳层、导航、URL 持久化、页面级重置和一级详情抽屉状态。
- `select` 模式下关联链接只更新当前预览或显示“前往图鉴”；用户明确前往时先关闭工作抽屉再导航。
- `selectedIdentity` 与草稿由配装器持有，异步请求只能返回数据，不能在复用组件内部直接改写七槽。

## 4. 武器与防具选择

`EquipmentPickerDrawer` 根据 `slot` 使用同一壳层、不同列定义。它不复制图鉴页面，而是调用对应图鉴的搜索、筛选、列表行、详情和图标组件，并传入 `mode="select"`、当前身份与选中回调；页面壳层、URL 同步和一级关联抽屉逻辑不进入选择模式。

### 4.1 武器

顶部水平筛选：

```text
关键词｜武器类型｜属性｜稀有度｜孔位｜可直接生产｜排序｜重置
```

- 结果表展示图标、名称、类型、攻击、属性、会心、OOO、稀有度和关键专项摘要。
- 右侧预览复用武器详情组件的只读核心信息；关联对象不得在选择抽屉内再开详情抽屉，用户点击时先关闭工作抽屉，再跳转对应图鉴并定位。
- 单击结果只选中预览；固定底栏的“应用选择”是明确确认路径，鼠标双击作为熟练用户的快速应用操作，结构不可编码的候选仍禁止应用。
- 自动配装要求一把具体武器；若尚未选择，启动搜索按钮禁用并在武器行就近提示。

### 4.2 防具

部位由打开工作抽屉的槽位固定，不再显示部位筛选。顶部水平筛选：

```text
关键词｜职业｜性别｜稀有度｜孔位｜技能｜技能点排序｜防御排序｜重置
```

- 结果表展示图标、名称、职业、性别、稀有度、OOO、基础/最大防御和主要技能点。
- 技能筛选选择技能系；若选中技能，支持该技能点降序。普通模式不显示与所选部位无关的记录。
- 右侧预览显示全部技能点、耐性、制作信息和当前配装替换前后差值。
- 不兼容当前武器职业或性别的防具默认隐藏；“显示不兼容/未确认”打开后允许选择，但在候选行、预览和应用确认区同时列出原因。只要身份和字段可编码，就不禁用手动选择。

### 4.3 MH4G 发掘装备高级编辑

配装器手动模式允许 MH4G 发掘武器和发掘防具进入七槽；候选来源使用配装专用发掘模板或导入实例，不把发掘条目重新塞回普通图鉴。候选行显示“发掘”徽标，选择后可从同一右侧抽屉切换“基础 / 发掘高级 / 原始记录”三个子视图。参考旧 MH4G 修改器的类型化字段分组，但不复制其通用字节表误导：

- 每件发掘装备必须携带完整 28 字节实例和来源 `catalogTemplate / importedLoadout / saveInstance`；当前阶段主要创建前两种，`saveInstance` 留给存档桥接。任何编辑都生成字段补丁，不从表单值重建整条记录。
- 发掘武器按武器类型显示攻击档、真实攻击、面板攻击、属性/异常类型及数值档、斩味方案或远程专项档、升级档、武器专属值、孔数、动态稀有度、研磨要求、发光/未研磨、极限强化，以及操虫棍猎虫等级/类型/力量、耐力、速度和五属性实例值，或轻重弩弹匣、速射/蹲射、限制解除及配件原始位。
- 发掘防具显示防御档、五耐性档、升级档、孔数、动态稀有度、研磨要求、发光/未研磨和三个带固定标志的装饰品记录。
- 武器、防具的三颗装饰品都保留 16 位原始值及 `bit15` 固定/内置标志；孔数与实际珠子允许不一致，作为非法但可编码状态提示，不擅自修复。
- 每一字段都显示“代码 / 可解释值 / 证据状态”；未知代码提供“保留原值 `0xNN`”，不自动改成默认值。
- 自定义原始值允许 `00–FF`（16 位字段允许完整存储宽度），修改采用字段级掩码，只改目标位，未知保留字节原样保留。
- 发掘选项字节 `0x10` 只允许以掩码修改 `bit0` 未研磨、`bit1` 发光和 `bits2–3` 孔数，高四位始终保留。轻重弩 `0x01` 的限制解除/配件未确认位同样按位补丁；未确认前不得重新编码整个字节。
- 普通武器/防具若携带发掘参数，显示“普通 ID 携带自定义字段；当前只读保留”提示，不因切换基础名称而清零。
- 候选操作使用“以此模板创建”，创建后克隆出页面级独立实例；后续高级编辑只修改该配装草稿，不得反向污染共享模板或同一模板创建的其他配装。
- 手动配装可以保存发掘参数和非自然组合；自动搜索不枚举或生成发掘随机参数，但用户明确固定且关键贡献可解码的发掘武器/防具可作为常量输入，结果不得覆盖其装备身份、高级字段、保留字节或已固定珠子。
- 候选筛选提供“全部 / 仅普通 / 仅发掘 / 含未确认”，默认“全部可编码记录”；这与自动搜索的“只生成普通自然候选”是两套明确语义。

## 5. 护石选择与校验

护石不渲染十几万自然组合。`CharmPickerDrawer` 使用结构化表单：

```text
护石品级｜孔位 OOO
A 技能｜A 点数
B 技能｜B 点数
自然范围状态｜规则来源
```

- 先选品级，再选孔位和技能；后续选项根据前项实时收窄，但已经输入的冲突值不被静默删除。
- A/B 技能使用可搜索下拉，搜索中、英、日名称及发动效果；点数控件同时支持键盘步进和直接输入。
- 点数旁始终显示当前合法范围，例如 `+2～+6`；范围不连续时以多个段落/选项显示，禁止合成一个过宽区间。
- `slotCount` 有精确共存证据时按精确规则校验；只有理论 `maxSlots` 时显示“孔位上限”，不得暗示最大点数必然与最大孔共存。
- 默认按自然范围提供快捷值；“自由编辑”展开后允许输入字段宽度内的任意值。非法但可编码的值保留为 `manual` 并明显标记；自动搜索不生成这类候选，但用户可将其作为固定输入原样保留。
- A/B 相同技能、空技能带非零点数、超过编码范围等行为由游戏规则插件判定，UI 只展示明确诊断。
- 底部“应用护石”只要求字段结构可编码；自然性警告、明确非法和编码错误分级显示，只有编码错误不能提交。

### 5.1 MH4G 护石自由编辑

MH4G 护石沿用旧修改器已经由真实存档确认的完整 28 字节类型视图，不把它误套成普通防具或发掘防具：

| 字段 | 记录位置 | 编辑规则 |
| --- | --- | --- |
| 装备类型 | `0x00` | 固定为护石类型 6；类型错误属于结构阻断 |
| 孔数 | `0x01` | 普通快捷值按自然规则，自由编辑按字段宽度保存 |
| 护石品级/ID | `0x02–0x03` | 16 位；未知但可编码 ID 保留并标记 |
| 装饰珠 1～3 | `0x06–0x0B` | 三个 16 位值，`bit15` 为固定标志，低 15 位为珠 ID |
| A 技能 ID | `0x0C–0x0D` | 16 位；未知 ID 显示“未知技能 #ID”，不得替换为“无” |
| A 技能点 | `0x0E–0x0F` | 有符号 16 位；允许字段范围内任意值 |
| B 技能 ID | `0x10–0x11` | 16 位；与 A 位分开校验，不合并 |
| B 技能点 | `0x12–0x13` | 有符号 16 位；允许字段范围内任意值 |
| 保留字节 | `0x14–0x1B` | 只读显示并逐字节原样保存 |

- 默认视图提供自然范围快捷输入；展开“自由编辑”后不再以正常掉落上限钳制技能点。真实样本中的未知技能 ID、`+30` 等非自然值必须能显示、计算、导出和再次导入。
- 自然范围、孔位共存、重复技能和空技能非零点数只产生 `invalid/unknown` 警告；技能 ID/点数超出 16 位、珠 ID 超出低 15 位或记录不是 28 字节才产生 `blocked`。
- 护石的孔数、实际三颗珠子和 `bit15` 固定标志分别编辑。超孔或孔数与珠子记录不一致允许应用并显示差额，不能静默删除珠子。
- 切换护石品级或技能不会自动清空另一技能位、珠子和保留字节。若新组合不自然，保留草稿并就近显示原因。

## 6. 逐件装饰珠编辑

`DecorationEditorDrawer` 始终绑定一个具体槽位，直接复用装饰品搜索、技能筛选、排序、列表行和详情组件，并使用左右双栏：

```text
左：可用装饰珠列表              右：当前这件装备
搜索 / 技能 / 占孔 / 排序       天然 OOO、已用、剩余
名称 / OOO / 全部正负技能点      已安装珠子列表
“添加”按钮                     “移除”按钮与技能变化预览
```

- 使用 `EquipmentSlotIndicator` 统一显示孔位。孔位按真实占用计算，不以珠子数量代替孔数。
- 点击“添加”后立即更新抽屉草稿和技能差值；孔位不足的珠子仍允许在“自由编辑”模式添加，同时显示“超出 N 孔”。默认模式保留可见并标出超孔风险，不静默隐藏。
- 已安装珠子逐颗显示，支持键盘移除；相同珠子可以合并显示数量，但减少一次必须有明确按钮。
- 列表展示每颗珠子的全部正负技能点。选择了技能筛选时，默认按该技能正向点数降序、占孔升序。
- 胸部装珠时预览胴系统带来的实际放大结果，但保存的仍是原始珠子贡献，避免重复计算。
- “应用”一次替换该槽位的珠子数组；“放弃”恢复进入抽屉前的完整数组。超孔和未知珠子属于风险，不自动清除；只有珠子 ID 或记录数量无法编码时阻止应用。

### 6.1 合法性、自由编辑与阻断边界

自然合法性和结构可编码性是两条独立状态轴，任何组件都不得用一个红色“非法”标签同时表达两件事：

```text
自然合法性：confirmed | invalid | unknown
结构可编码：encodable | blocked
```

| 状态 | 含义 | 手动应用 | 自动配装 |
| --- | --- | --- | --- |
| `confirmed + encodable` | 符合已确认自然规则 | 允许 | 可生成，也可固定 |
| `invalid + encodable` | 明确不自然，但字段可以保存 | 允许并警告 | 不生成；明确固定后可作为常量输入 |
| `unknown + encodable` | 证据不足或含未知原值 | 允许并提示来源 | 不生成；关键贡献可计算时可固定 |
| `* + blocked` | 记录长度、字段位宽、身份或编码结构错误 | 禁止 | 禁止开始或应用结果 |

- 手动模式必须允许字段宽度内的非自然护石、超孔装珠、未知珠子、性别/职业不兼容装备、发掘越界档以及普通 ID 携带的自定义字段；这些状态不被静默钳制、清空或替换。
- 每个问题在对应字段或装备行附近显示文字原因和证据来源；页面顶部可另有风险摘要，点击摘要必须定位到字段。不能只使用 toast，也不能只依赖红/黄颜色。
- 字段下方预留稳定的诊断区域，警告出现时不推动整张表或导致抽屉内容跳动。多个问题按“阻断错误 → 明确非法 → 未确认”排序。
- 每条诊断包含稳定问题码、严重级别、字段路径、简短原因、证据来源和建议操作；颜色只做辅助，图标与文字必须同时存在。
- 只有不可编码身份、记录不是完整 28 字节、数值超出实际字段宽度、数组超过记录容量或无法生成字段补丁时禁用“应用”。自然范围、孔位、职业和性别冲突只影响合法性，不直接阻断。
- “应用前复核”同时返回两套状态；确认对话只用于汇总高风险可编码值，不得把警告伪装成无法继续的错误。
- 警告确认只针对本次新增或改变的风险；导入时已经存在且未被触碰的风险继续显示，但不要求每次切换预览都重复确认。

## 7. 自动配装工作区

自动配装使用同一个大型 `LoadoutWorkspaceDrawer`，分为“条件”和“结果”两个顶层标签，不做不可回退的线性向导。条件修改后旧结果标记为“条件已变化”，但保留到用户重新搜索。

### 7.1 必选条件

顶部固定显示：

```text
具体武器｜性别｜目标发动技能｜搜索按钮
```

武器是必填的具体实体，不接受抽象的“3 孔武器”。没有武器或没有目标技能时，就近显示原因并禁用搜索。

### 7.2 多技能目标

新增目标使用可搜索组合框，搜索范围包括技能系、发动效果及中英日名称。候选格式固定为：

```text
弱点特效｜技能系：痛击｜需要 +10
攻击力提升【大】｜技能系：攻击｜需要 +20
```

选中后进入目标列表，每行显示：

```text
发动效果｜技能系与阈值｜硬目标标记｜上移/下移｜移除
```

- 首版所有目标都是“必须发动”的硬约束；排序只影响展示和搜索启发式，不降低任何目标的满足要求。
- 自动目标只提供正向发动效果；负面效果作为结果风险和可选排除条件，不允许误选成目标。
- 同一技能系选择多个等级时自动保留最高阈值，并给出合并提示；不能同时要求“攻击小”和“攻击大”形成重复约束。
- 复合技能使用稳定 `activationKey`。若其组件关系能够被规则插件精确计算，则作为一个目标；否则禁用并解释缺少的规则，不拆成猜测条件。
- 支持关键词粘贴后逐项添加，但不依赖自由文本解析生成未确认技能。

### 7.3 固定装备

条件页显示与主页面相同的七槽紧凑表，每槽用可键盘操作的三项单选组明确固定范围：

- `未固定`：自动搜索可以替换该槽。
- `固定装备`：保留具体装备/护石实体，但默认允许求解器重新分配该槽珠子。
- `固定装备和珠子`：保留实体以及当前装饰珠数组。

三项使用文字、锁图标和选中标识共同表达，并提供 `radiogroup`/`radio` 语义，不能只靠锁图标颜色。武器实体始终固定，但武器珠子仍可在“固定装备 / 固定装备和珠子”间切换。护石固定时保留品级、孔位、A/B 技能及点数；非法或 `manual` 护石不会被求解器生成，但只要可编码，用户明确固定后可以原样参与计算且不得被改写。

主页面已选择不代表自动固定。首次打开自动配装时继承当前实体作为候选初值，但所有未被用户显式锁定的槽仍为“未固定”；主页面已经明确锁定的槽保持“固定装备”，武器实体始终固定。这样既不会误收窄搜索范围，也不会丢失用户预先设置的锁定意图。

需要更换某个固定实体时，从同一个 `LoadoutWorkspaceDrawer` 进入选择器子视图：

```text
自动条件 → 选择头部防具 → 返回自动条件
```

返回时保留全部目标、锁定和高级条件；禁止再打开嵌套工作抽屉。

### 7.4 高级条件

默认折叠，包含：允许位阶/稀有度、最低防御、耐性下限、禁用装备、禁用技能、自然护石范围、最大结果数、超时和排序权重。普通用户只需选择武器和目标技能即可搜索。

候选生成始终排除 MH4G 发掘模板、占位记录、非法护石和超孔组合，不提供将这些内容纳入自动枚举的开关。用户已明确固定的可编码发掘/非法/不确定实例不属于候选池：它们作为常量输入保留，求解器只搜索其余未固定槽和允许重新分配的珠子。

开始搜索前先检查固定实例：若技能、防御、耐性、孔位等求解所需贡献可解释，则允许继续并显示“结果将包含手动非法/未确认输入”；若关键贡献无法计算或记录不可编码，则就近阻止开始并列出具体字段，不能笼统写成“不支持发掘装备”。

### 7.5 搜索进度与结果

开始搜索后切换到结果标签，顶部固定显示阶段、已检查状态数、结果数、耗时和剩余时间估计，并提供暂停/继续/取消。取消只结束 Worker，不修改当前配装。

结果列表采用“一项结果一张七槽表格”，避免把装备名、装饰珠和孔位挤在单行中：

```text
结果摘要：防御/最大｜五耐性｜剩余孔｜风险｜选择状态
七槽明细：部位｜装备｜装饰珠｜孔位占用
```

- 每张表固定展示武器、头、胸、腕、腰、腿、护石七行，装备和珠子名称允许换行，孔位同时表达天然孔、已占孔和剩余状态。
- 结果支持推荐顺序、防御力降序和剩余孔数降序；排序使用稳定 fingerprint 处理平局。
- “应用此结果”前再次调用正式计算器和编码校验器复核。复核通过后一次性替换内存配装，并关闭工作抽屉；失败则保留结果并显示具体数据版本、字段或规则原因。
- 含固定 `invalid`/`unknown` 实例的结果必须显示“包含手动非法/未确认输入”，并列出继承的问题；结果满足目标技能不等于这些输入已经变成自然合法。
- 固定实例分为“固定装备”和“固定装备和珠子”。前者允许求解器重新分配普通可编辑珠子，但不得触碰发掘防具/武器的 `bit15` 内置珠、未知珠或未知原始位；后者连同全部珠记录逐字节固定。
- 相同输入和 `dataVersion` 使用稳定排序与 fingerprint；加载新结果时保留旧预览，避免详情闪烁。
- 空结果给出可行动原因，例如“固定胸部后痛击最高只能达到 8/10”，而不是只显示“无结果”。

### 7.6 持久任务与历史管理

自动搜索不再归 `AutoLoadoutDrawer` 的组件生命周期所有，而由主进程级 `AutoLoadoutJobService` 统一管理：

- 创建任务时先写入 `<userData>/state/loadout-jobs.sqlite`，再启动 Worker；条件、基础配装、目标、时间预算、节流进度、结果和终态均为本地持久记录。
- 全局同时最多运行一个 Worker，后续任务按创建顺序进入队列；当前任务结束、取消、失败或删除后自动启动最早的排队任务，避免多个搜索同时占满 CPU 与 Swap。
- 关闭自动配装抽屉、切换其他配装操作或暂时离开结果视图都不会取消任务。重新打开自动配装时恢复最近任务的原始条件、固定槽、时间预算、进度、状态和结果。
- 应用退出前终止活动 Worker，并把遗留的排队、运行或暂停任务标为“已中断”；首版不保存求解器组合检查点，可通过“按原条件重跑”创建带父任务 ID 的新记录。
- 配装器工具栏提供“历史任务”入口和活动/未查看徽标；仍复用同一个 `LoadoutWorkspaceDrawer`，按“历史列表 → 条件/进度/结果”切换，不新增路由或嵌套抽屉。
- 历史支持关键词、游戏和状态筛选，可暂停、继续、取消、重跑、单项删除和批量清理终态记录。删除活动任务必须确认并先终止对应 Worker。
- 历史结果跨游戏只读；同游戏应用时先按当前资料版本重新水合并调用正式计算器复核目标、孔位和编码状态。旧版本结果仍可查看，复核失败时保留记录和错误说明。
- 每个结果使用不可收缩的独立七槽表格；主页面、自动条件和结果表统一使用 `LoadoutSlotIcon`，优先显示装备真实 `iconPath`，缺图或空槽使用武器/部位/护石 SVG fallback，并保留可读名称。

## 8. 草稿、撤销与本地状态

- 选择装备、编辑护石和装珠均在工作抽屉草稿中完成；取消不修改当前配装。
- 应用每次操作后写入页面级撤销栈，至少支持撤销/重做最近的装备、护石、装珠和自动结果应用。
- “新建配装/清空全部”是破坏性本地操作，存在内容时必须确认；单槽清空可直接执行并支持撤销。
- 完整配装不写进 URL。URL 只保留当前页面和非敏感视图状态；逻辑配装通过内存 store 与版本化 `.mhloadout.json` 管理。
- 导入后按当前数据库重查所有身份并重新计算；数据版本不兼容时显示逐项迁移结果，不静默替换同名装备。

## 10. 可访问性与键盘路径

- 右侧工作抽屉使用 `role="dialog"`、可读标题、焦点锁定和焦点归还；视觉上从右侧滑入，不改变主页面宽度。
- 表格行选择、锁定、装珠和应用是独立原生按钮；紧凑锁定控件使用 `aria-pressed` 和可见焦点环。
- 装备候选列表支持上下键移动、Home/End、PageUp/PageDown；Enter 更新预览，应用仍由明确按钮完成。
- 技能目标列表的上移/下移按钮提供完整可读名称，不只显示箭头。
- 搜索进度使用节流后的 `aria-live="polite"`；高频计数不逐条播报。
- sticky 表头和底部操作栏不得遮住键盘焦点；滚动容器设置适当的 `scroll-padding`。
- `prefers-reduced-motion` 下取消抽屉位移、列表重排和进度插值，只保留状态切换。

## 11. 验收场景

### 手动配装

- 未读存档时选择具体武器、五件防具和护石，并逐件安装/移除珠子。
- 更换近战武器为远程武器时明确列出不兼容防具，不静默丢失选择。
- 护石 A/B、正负点数、不连续范围、孔位证据和非法手动值均能正确反馈。
- MH4G 发掘武器/防具可从配装专用模板创建并进入高级编辑；字段级修改后完整 28 字节记录的非目标位保持逐字节一致。
- 护石任意有符号 16 位点数、未知技能 ID、超孔珠和未知保留字节可在可编码范围内保存，且均显示明确风险而不被自动修复。
- 胸部珠子、一个或多个胴系统装备的矩阵贡献可解释且计算一次。
- GU/XX 同时发动护石强化和秘术时，固定验证 `x × 2 + 2`，包括负数和阈值边界。

### 自动配装

- 可添加多个具体发动效果；同技能系多等级能合并为最高阈值。
- 每个槽可在未固定、固定装备、固定装备和珠子三种状态间切换。
- 自动搜索不会生成 MH4G 发掘装备、占位装备、非法护石和超孔组合；用户明确固定且可计算、可编码的 `invalid`/`unknown` 实例作为常量保留，求解器不得改写。
- 固定发掘武器、固定发掘防具、非自然护石和超孔珠分别有样本；结果显示继承风险，无法解释关键贡献或无法编码时才阻断。
- 暂停、继续、取消和超时不会冻结页面；旧请求不能覆盖新请求。
- 结果应用前经正式计算器复核，应用操作可撤销。
- 关闭抽屉后任务继续运行，重新打开时条件、进度和结果完整恢复；应用重启后未完成任务转为“已中断”，已完成历史仍可查看和重跑。
- 同时创建多个任务时只有一个 Worker 运行，其余任务按创建顺序排队；删除活动任务后队列继续推进。
- 历史结果使用当前 `dataVersion` 重新水合和复核，跨游戏结果不能误应用到当前配装。

### UI

- 选择器和自动配装切换子视图时只有一个工作抽屉，页面不会横向偏移，也不会出现嵌套遮罩。
- 1024px、1280px、1440px 下窗口整体不滚动；装备表、详情和结果区各自内部滚动。
- 全流程可只用键盘完成；焦点顺序与视觉顺序一致，关闭工作抽屉后回到原按钮。
- 文本、数据、孔位和状态只使用项目全局令牌；滚动条沿用低对比棕金样式。

## 12. 实施顺序

1. 冻结 `Loadout`、锁定状态、技能目标和草稿/撤销协议。
2. 实现纯计算器及 GU/XX `x × 2 + 2` 固定夹具。
3. 实现 `LoadoutWorkspaceDrawer` 和七槽主页面骨架。
4. 实现武器/防具选择器及替换差值预览。
5. 实现护石编辑和自然范围校验。
6. 实现逐件装珠与实时技能矩阵。
7. 实现自动条件、多技能目标、三级固定状态和 Worker 生命周期。
8. 实现结果对比、正式复核、应用及撤销。
9. 实现本地 `.mhloadout.json` 导入导出。

本轮不实现装备箱导入、一键写回、发掘装备自动生成、配装广场上传或在线同步。

实施结果：七槽全宽工作台、四类一级工作抽屉、当前快照重水合导入、替换差值、护石自然/编码双范围、超孔装珠、发掘高级字段、多目标优先顺序、三级固定状态、Worker 生命周期和应用前复核均已落地。选择器支持可搜索筛选、服务端分页、双击快速应用与方向键/Home/End/PageUp/PageDown 定位；抽屉以 portal + fixed 覆盖正文，Escape、焦点锁定和焦点归还由公共壳层统一处理。

性能与一致性复核：页面首次进入只读取技能、珠子、护石规则和筛选面，不再向 renderer 传输完整武器/防具候选；武器、防具在选择抽屉打开后按需分页读取，导入和自动搜索仍在主进程取得完整快照。防具技能与装饰珠技能关系由一次分组索引替代逐装备全表扫描。全项目滚动条统一继承 ui/styles.css 的棕金令牌，护石表单和可搜索下拉均可独立滚动且不会因滚动关闭。
