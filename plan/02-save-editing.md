# 阶段 2：五种存档格式编辑闭环

当前状态：主体实现完成，进入 Windows 模拟器重开验收与真实样本扩充（2026-09-11）

图鉴阶段和不依赖存档的配装器 3A 已经完成，本阶段现正式成为开发主线。实现顺序固定为：格式探测与真实样本登记 →
只读解析 → 字段级补丁 → 校验/加密 → 原子保存。任何格式在真实样本、no-op round trip
和单字段精确 diff 未通过前，保持实验状态，不进入正式支持声明。

当前阶段边界：五格式 adapter、会话、修改工作区、箱子传输、图鉴加入和配装结果一键写入已经接入。
后续只在真实样本与对应模拟器重开通过后提升正式支持等级；图鉴的数据增补和视觉精修均为非阻塞维护。

## 0. 当前阻塞摘要

- 防具原生身份数据已经找齐：MH3G 原 51 条缺口 `51 / 51` 唯一闭合，MHGU/XX 原 154 条缺口

  16 条美版独占记录应明确对日版存档禁写，而不是强行映射。
- 三作旧配装器已经实现事务式一键加入装备箱，既有构造器和完整 record 直接作为新桥接基础；
  GU/XX 从零新建操虫棍的默认猎虫模板是单项实现与测试，不阻塞其他装备或整套写入。
- 配装器 raw instance schema 已兼容 16/28/36 字节并可附带 `SaveFormatId`；写入时会再次与当前
  adapter 的 record size 和格式核对。
- 本轮不编辑当前穿戴、随身背包或快捷栏；物理换位保持隐藏。GU/XX 逻辑 CSV、完整备份与原子覆盖
  已实现，Windows 文件占用和模拟器重开仍是平台验收工作。
- GU/XX 猫猫等级与 EXP 仅按原值只读展示；倾向、行动、技能、外观按 324 字节记录做字段级补丁。
  普通编辑保持当前 pattern、有效长度和尾部哨兵；切换倾向时可在确认预览后按原生 A/B/C 规则重建，
  训练/设施/引用始终保持只读。
- 新 TypeScript adapter 的五份私有真实样本 no-op 已通过，但样本来源登记、三槽真实文件、特殊装备/

因此当前不存在需要继续等解包或 Wiki 的功能阻塞。detector、Blowfish、按格式 record、CSV 和原子

## 1. 功能范围

每种支持格式至少实现：

- 格式自动识别与持续可见的版本提示
- 角色槽选择
- 玩家基础信息读取与修改
- 道具箱读取、修改、批量操作和逻辑 CSV 传输
- 装备箱读取、按类型编辑、批量操作和逻辑 CSV 传输
- 保存前校验、备份、原子写入和修改摘要

本阶段不支持实体机容器，也不执行跨游戏整档转换。

## 2. 公共存档模型

```text
SaveIdentity
├── contentGame
├── formatId
├── platform
├── emulator
├── region/version
├── characterSlot
└── confidence/evidence

SaveDocument
├── identity
├── originalBytes
├── player
├── itemBox
├── equipmentBox
├── gameSpecificSections
├── dirtyPatches
└── diagnostics
```

`originalBytes` 是保存的权威基底。解析后的领域对象用于显示和编辑，最终由明确的 patch writer 写回
原始缓冲区。不得根据已知字段重新序列化整份文件。

## 3. Adapter 分层

每个格式拆成小模块：

```text
detect.ts       尺寸、magic、校验和、结构证据
layout.ts       偏移、长度、槽数和端序常量
reader.ts       只读解析
writer.ts       字段级补丁
validator.ts    结构、范围和业务风险
checksum.ts     校验和/加密边界
fixtures.ts     测试辅助，不进入生产导出
index.ts        对外 adapter 组合
```

共享 `binary` 工具集中提供有符号/无符号整数、大小端、定长字符串、位字段、边界检查和 diff。禁止
在页面或 repository 中直接写偏移。

## 4. 各格式迁移重点

### MH3G 3DS / Citra

- 迁移 `mh3u-se` 已验证的 3DS 文件头、角色槽、道具箱、装备箱和玩家字段。
- 保留 `user1/user2/user3` 识别和错误槽位拒绝逻辑。
- 用真实样本验证 no-op round trip 和单字段 diff。

### MH3U Wii U / Cemu

- 与 MH3G 共用内容 catalog，不共用文件布局。
- 明确处理 Wii U 文件头和大小端差异。
- UI 始终显示“MH3U · Wii U · Cemu”，不能笼统显示 MH3G。
- 3DS/Wii U 只允许逻辑道具/装备传输，不把整份文件互转。

### MH4G 3DS / Citra

- 迁移 Blowfish 解密、结构校验、重新加密和校验和流程。
- 解密缓冲区只存在于受控主进程内存，不写临时明文文件。
- 装备实例保留 28 字节原始记录、固定珠标记、发掘参数、护石 16 位技能点和猎虫信息。
- 未知或非自然组合给出诊断，不擅自修复或清零。

### MHGU Switch / Yuzu

- 支持三角色槽、玩家信息、道具箱、猎人装备、猫装备和猫猫相关已验证字段。
- 装备实例保留 36 字节记录及未知字节。
- 防具幻化按已验证规则处理；原版武器幻化不作为正式功能。
- 选择存档后显示“MHGU · Switch · Yuzu”。

### MHXX 3DS / Citra

- 使用独立 `mhxx-3ds-citra` adapter，不能依靠 MHGU adapter 猜偏移。
- 与 MHGU 共用内容 ID/profile，但分别校验文件尺寸、文件头、槽位基址和每槽边界。
- 当前真实样本不足的部分在完成前保持实验状态，不进入正式 release 支持声明。
- 选择存档后显示“MHXX · 3DS · Citra”。

## 5. 玩家信息

公共玩家字段按 capabilities 展示，例如名称、性别、金钱、点数、游戏时间和角色外观。游戏特有字段
放在 adapter 的扩展 section 中，不为了表面统一而强行制造无意义字段。

每个字段定义：

- 读取位置和长度
- 编码/端序
- 可写范围
- 空值规则
- 修改后的精确字节范围
- 是否影响校验和或加密

无法确认的字段只读显示或完全隐藏，不以“高级模式”为由允许盲写。

## 6. 道具箱

- 保留空槽、数量、道具 ID以及游戏已知标记。
- 输入允许按名称搜索，最终保存真实 `save_id`。
- 数量超限、DUMMY、未知 ID 给出明确错误或警告。
- 批量填充、清空和导入操作先在临时模型验证，确认后一次提交。
- CSV 只传逻辑字段和协议版本，不包含文件偏移。

## 7. 装备箱

- 一个箱子格是实例，必须保留完整 raw record。
- 武器、防具、护石、猎虫、随从装备按各自字段视图编辑。
- 普通固定装备允许从图鉴创建合法基础实例。
- 已有发掘/自定义实例允许在证据覆盖范围内编辑，但不凭空合成未知参数。
- 装饰珠槽位与固定标记必须跟随实例，不归并成顶层珠子列表。
- 导入和一键写入先检查容量；失败时装备箱保持完全不变。

## 8. 保存事务

保存流程固定为：

```text
重新验证当前文档
→ 将 dirty patches 应用到原始字节副本
→ 重算必要校验和/加密
→ 写入同目录临时文件
→ flush/fsync
→ 可选生成带时间戳备份
→ 原子替换目标
→ 重新读取并探测输出文件
→ 更新内存基线
```

另存为可以创建新文件；覆盖原文件必须经过用户明确操作。保存失败时不能留下半写文件，也不能把
内存 dirty 状态误清空。

## 9. 最小 UI

阶段 2 只要求：打开、格式确认条、角色槽、玩家表单、道具箱表格、装备箱表格、编辑抽屉/对话框、
修改摘要、保存与另存为。每个页面和组件仍遵守 `AGENTS.md` 的独立 `.tsx`/`.css` 规则。

## 10. 验收门槛

每个正式格式均需通过：

- 正确样本可以识别，错误游戏和截断样本不能误识别。
- 打开后不修改，保存结果逐字节相同。
- 每个玩家字段都有单字段精确 diff 测试。
- 道具箱和每种装备类型都有读取、修改、撤销、保存、重开测试。
- 未知字节在已知字段修改后保持不变。
- 加密格式解密/重加密后可以被新 adapter 和旧已验证实现读取。
- 箱子已满、非法 ID、超范围值、写入失败均不会产生部分修改。
- 保存前后显示的格式标识不发生漂移。
