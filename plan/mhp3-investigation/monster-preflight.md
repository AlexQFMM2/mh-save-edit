### 已发现的身份陷阱

原版存在两组各 75 个槽位的相关文本，其中一组省略部分亚种／稀少种后缀，另一组保留较完整名称。它们含 `NO DATA`、搬运／宅配猫、山菜爷和岩石等对象，不能把 75 当作怪物数，也不能把两组当成两套不同怪物。

较完整名称区中，飞甲虫对应 4 个不同显示编号，垂皮龙对应 2 个；同名不能合并。参考小型页还单列卵块对象，其原文含旧称，需核对实际对象和上下文，不套用同名怪物的命名规则。正常物种、原生实例／变体和特殊对象的最终计数，要由对象主表、消费者及本作出现场景共同确认。本轮保留完整原文候选，不生成运行身份。

## 接入前需要补齐的证据

| 事项 | 当前具体缺口与退出条件 |
| --- | --- |
| **原生身份与目录** | 从显示消费者继续追对象定义和资源选择，核对记录起点／步长／数量／终止、指针基址及编号范围，明确原种、亚种、稀少种、同名变体、卵块、NPC 与环境物件。单独绑定名称、说明、图标、数值、奖励和出没关系；不按名称槽、模块名或顺序创建身份。建立与独立 P3 资料的显式 crosswalk，并记录目录筛选依据 |
| **肉质与部位／状态** | 原生字段布局、斩／打／弹和五属性列、气绝字段及状态切换尚未审计。参考确认雷狼龙有通常／超带电两套肉质，土砂龙有泥层变化，岚龙有形态差异；不能只取第一组或把未标注状态显示为“通常”。需核对部位对应、状态触发及完整数值组，保留未知部位和条件。怯值、部位耐久与肉质不是同一量，不能混填 |
| **异常与控制** | 需要明确初始耐性、增量／上限、蓄积衰减、持续时间单位，以及每次伤害、每秒伤害和总伤害的区别。P3 还涉及减气、疲劳、重复控制耐性和特定状态免疫。参考雷狼龙页面明确记有麻痹陷阱在超带电时失效及通常／疲劳／重复使用条件；这些尚待本作消费者或逐项独立对照，不能压成一条无条件“有效＋持续时间”。未知、不适用、已知无效必须分开 |
| **掉落与道具双向关系** | 原生剥取、捕获、部位破坏、掉落物、背部采集等表及消费者尚未闭合。需核对位阶／特殊任务条件、道具 ID、每次数量、尝试次数、概率单位及池边界。雷狼龙参考资料区分村★2特例、一般下位和上位，并有背部捕虫；峯山龙区分头／体剥取、口内和背部采矿。不能把“剥取 3 次”显示成每次产物数量 ×3，不能把池概率当整场取得率。所有关系引用现有 P3 `itemId`，做全量端点及正反查审计 |
| **中文与原生图标** | 名称候选须逐条核对来源、亚种区分和语义，保留日文、别名与来源；GU 未匹配项继续查已有审定用词及其他官方来源，必要时项目翻译。怪物图标尚无完整编号→选择函数→纹理坐标／调色板／透明度契约；装备和道具图标不能替代怪物图标。需单独追踪和独立像素验证，不能按图集顺序或相似图片配图 |
| **出没任务与来源覆盖** | 旧研究验证了 332 个任务封装的结构校验，但任务 ID、怪物目标／乱入、地图、倍率等尚未全部绑定，不能把封装数量当完整任务覆盖。独立怪物页有出没表，且包含活动、挑战、乱入、召唤和非目标个体；需要保留来源及条件。先提供有证据的最小出没预览和明确覆盖状态，不以完整任务图鉴作为本轮硬前置，也不生成假任务 ID／占位跳转 |

上述参考实例用于确定必须保留的字段和条件，本轮没有把其中的精确数值升级为原生已验证机制。来源冲突按字段保存双方版本与采用理由；未解释原生字段可在逐项核对后明确显示独立来源，不为追求“全部原生”阻断已有可靠资料，也不伪装证据等级。

## 工程接入与复用边界

1. **复用完整库和既有对象身份。** 在完整 P3 库副本追加怪物、必要的掉落／出没关系及版本标识；道具名称和身份继续由原道具表负责。构建只读冻结输入，核对现有 20 张业务表指纹及其他作品哈希。仅追加怪物资料不改变道具词典绑定输入，无须重建词典。
2. **只扩大怪物领域能力。** [类型](../../api/catalog/types.ts)、[schema](../../api/catalog/schemas.ts)、[IPC](../../api/catalog/ipc.ts)目前使用不含 P3 的怪物身份；新增领域级 `MonsterCatalogGameId`，同步 preload／renderer 声明、关联目标和只读 repository。沿用 `searchMonsters`、`getMonster`、`getMonsterFacets` 三条通道，拒绝跨作／混合／越界身份，不把 P3 扩入通用 `CatalogGameId` 或其他未实现服务。
3. **复用现有怪物页与表格，补必要的 P3 条件。** [MonsterCatalogPage](../../ui/pages/MonsterCatalogPage/MonsterCatalogPage.tsx)、[详情](../../ui/components/MonsterDetailPanel/MonsterDetailPanel.tsx)已有列表、URL、肉质、异常、掉落及关联入口。[异常表](../../ui/components/MonsterAilmentTable/MonsterAilmentTable.tsx)当前区分 P2G／其他作，非 P2G 分支把部分 `null` 显示为“不适用”；不能直接让 P3 使用这个默认语义。单个持续值也不足以覆盖重复次数／疲劳／形态条件，需要有明确单位和条件的本作详情。肉质表以空条件回退“通常”，P3 未知状态必须显式标注。
4. **真正打通怪物↔道具。** [P3ItemCatalogRepository](../../api/catalog/p3ItemRepository.ts)目前只有怪物来源未收录标记；来源筛选、关联搜索、命中原因和详情关系都要补齐。怪物掉落使用 `{ gameId: 'mhp3', itemId }`，不能走旧三作 `saveId` 路径。正文开一级抽屉，抽屉内关闭后定位，恢复焦点，保留选择与滚动。
5. **任务关联保留可用落点。** 共享怪物页当前会默认调用 `QuestDetailDrawer`，怪物抽屉的任务点击也直接生成任务图鉴路由；P3 尚无此服务。可参考 P2G 早期出没预览，将有来源的任务记录定位到怪物页内预览并保留返回路径，待任务专题再接正式身份。没有出没资料时说明尚未收录，不显示“0 个任务”暗示已查无。
6. **验收后再开放能力。** [App](../../ui/App.tsx)的 P3 怪物仍走占位入口。需覆盖旧完整武器库缺怪物资料、加载失败／重试、空筛选、目标不存在、同名身份、条件肉质、未知与无效、概率／数量、双向搜索、前进后退和单层抽屉。回归现有四作怪物与 P3 已有五类图鉴；真实资料检查 1440×900、1024×768 及正式 Electron，Windows／游戏验证单列。

建议实施顺序为：**对象身份与目录 → 原生肉质／耐性／控制及掉落关系 → 名称／图标 → 出没预览 → 完整库副本构建与共享页面接入 → 验收与本地安装**。每一步以字段和关系证据为依据，不以已有参考的条目数预设最终正常目录。未来任务图鉴可在既有 P3 身份和出没关系上接入，无须提前建设完整任务子系统。
