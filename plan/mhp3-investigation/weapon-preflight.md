## 当前结论

**可以继续武器专题，没有发现需要用户补文件、重新解包或另找 Dex 才能推进的硬前置。主要阻碍是武器数据契约尚未完成，不能把已定位的原生表直接接成完整图鉴。**

## 接完整武器页前的数据阻碍

| 阻碍 | 要补的证据与退出条件 |
| --- | --- |
| **核心数值与攻击强化** | 沿 P3 访问器、装备详情显示与判定确认攻击、会心符号、防御加成、属性／异常、孔位、稀有度及斩味。明确原始值和显示值的转换，不复制 P2G 武器系数。独立参考明确列有武具玉攻击强化和弩部件加成；需要分别核对本作计算、材料、费用及显示状态，不能把强化后数值当基础攻击，也不能当成新的派生武器身份。斩味另核对基础与匠的长度、截断及颜色段 |
| **生产、派生与材料关系** | 定位生产／升级表及其遍历消费者，确认步长、终止、目标类型／编号、父子边、材料 ID／数量、费用和替代路线。建立全量端点校验与材料反查；最终形态由完整出边判定。独立参考列出的锈块／风化系、初始装备等非普通生产来源也需核查，不能只靠有无生产配方判断正常取得。若存在跨类或回向边，保留原图 |
| **各类武器专属参数** | 铳枪：炮击类型与等级。斩击斧：瓶种类及对应属性／状态值。狩猎笛：音色、旋律顺序、效果及重奏语义，涉及时间或倍率时另核对本作消费者。轻／重弩：可用弹、实际装填量、装填／反动／偏移枚举、速射与蹲射关联。弓：蓄力段、装填数追加段、箭型／等级、曲射和瓶支持。P2G 没有的机制不能补成空值或借后作数据；弹／瓶关联要绑定本作道具 ID |
| **正常目录和特殊来源** | 对 987 个候选逐一形成原生身份与取得证据，分开记录正常、特殊用途和取得未确认；用生产／升级／初始／鉴定等已证明来源检查可达性，再与独立资料对照。参考缺失、表中存在、价格非零或名称正常均不足以定性。制作出现／任务进度未解析的部分可明确留缺口，不要求先做完整任务图鉴 |
| **审定名称与原生图标** | 逐项审阅 573 个 GU 候选并处理其余 414 个名称，保留日文、旧称、译名来源和原生键。道具／防具已验证的纹理解码与调色板工具可复用，但武器的类型／稀有度选择、坐标、颜色和透明度还需自己的消费者证据及像素对照；35 张防具图标不构成武器图标覆盖 |

独立参考中的武具玉强化、部件说明及专属字段目前只用于识别核查范围，本轮没有把其中的精确倍率或数值升级为原生已验证。名称／长篇说明入口已存在，但长篇说明翻译、动作值和完整伤害计算不作为这次前置核查的完成承诺。

## 工程接入点与复用边界

工程上没有发现必须重构全项目的前置，可以沿已交付的 [P2G 武器实现](../../docs/mhp2g/weapon-catalog.md)复用查询流程、页面和派生画布；P3 的数据和专属机制独立适配。

1. **本作资料作为唯一事实来源。** 在当前完整 `mhp3.sqlite` 副本追加武器、路线／材料、派生边及必要的专属资料。材料引用已有 P3 `itemId`；不复制另一套道具或技能名称。构建只读冻结输入，记录新资料版本、旧业务表指纹和其他作品哈希。武器名称不属于道具词典绑定输入，单独追加武器不需要重建词典。
2. **扩大武器领域能力。** 新增领域级 `WeaponCatalogGameId` 和 P3 原生武器契约；同步 [类型](../../api/catalog/types.ts)、[schema](../../api/catalog/schemas.ts)、[IPC](../../api/catalog/ipc.ts)、[preload](../../desktop/preload.ts)及 [renderer 声明](../../ui/env.d.ts)。复用 `searchWeapons`、`getWeapon`、`getWeaponFacets`、`getWeaponTree` 四条通道，分派到本作只读 repository；拒绝跨作／混合／越界身份，不把 P3 加进通用 `CatalogGameId`，不构造 `dexId`／`saveId`。
3. **扩展现有显示适配。** [catalogWeapon](../../ui/utils/catalogWeapon.ts)、[WeaponCatalogPage](../../ui/pages/WeaponCatalogPage/WeaponCatalogPage.tsx)及 [WeaponDetailPanel](../../ui/components/WeaponDetailPanel/WeaponDetailPanel.tsx)目前把原生分支视作 P2G；包含 P2G 专属笛谱／远程详情和写存档控制，不能仅将条件扩大为“P2G 或 P3”。保留共享列表、筛选、核心数值、斩味和派生画布，按 P3 契约接专属区及强化状态；本阶段保持只读。
4. **完成双向关联。** [P3ItemCatalogRepository](../../api/catalog/p3ItemRepository.ts)当前将武器用途标为 `not-collected`，需真正接上武器材料反查、关联搜索和命中原因。武器↔材料、武器↔派生，及接入的弹／瓶↔道具关系都要覆盖两向。正文开一级抽屉，抽屉内先关闭再定位；共享详情抽屉和页面中的 P2G 专用分支需一并调整。
5. **能力与回归一起收口。** [App](../../ui/App.tsx)的 P3 武器仍是占位路由。数据契约、schema／IPC 和共享页就绪后再开放；旧防具版库应明确提示武器资料未安装，不能静默返回空列表或落入其他作品。验收涵盖 12 类武器、替代配方、特殊取得、专属字段、筛选与派生命中、URL／历史、滚动和单层抽屉，并回归已接入作品；真实资料在 1440×900、1024×768 及 Electron 检查。Windows／游戏验收单列。

建议下一轮先做**原生核心字段与攻击强化 → 生产／派生／取得边界 → 各类专属参数 → 名称及图标审阅 → 完整库副本构建与页面接入**。字段语义、关系端点、正常目录、审定名称与图标满足功能要求后再开放页面；当前没有需要用户先准备新来源的阻碍。
