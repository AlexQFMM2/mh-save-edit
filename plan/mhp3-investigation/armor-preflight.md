## 工程接入点与最小完整路径

这部分是可以安排实现的适配工作，目前没有发现必须重构全项目的障碍：

1. **共用同一防具事实。** 当前 `p3_skill_armors` 与 `p3_armor_skill_points` 已拥有身份和技能关系；在当前完整库副本上扩展这些身份的资料，追加必要的配方、材料、套装关系。技能预览与新防具查询读取同一份名称、数值和技能点，不另建互不关联的防具副本。
2. **单独扩大防具能力。** 当前 `CatalogGameId`、防具 schema、IPC、preload、renderer 声明及 `ui/utils/catalogArmor.ts` 只接既有四作。新增领域级 `ArmorCatalogGameId` 与 P3 原生身份分支，贯通 `searchArmors`、`searchArmorSets`、`getArmor`、`getArmorFacets`；不把 P3 加入通用支持范围或伪造 `dexId`／`saveId`。`ui/App.tsx` 当前仍将 P3 防具交给占位页。
3. **复用既有页面与组件。** 使用 `ArmorCatalogPage`、筛选、单件列表、套装矩阵和详情。现有工具函数、详情及材料区域有 P2G／Dex 二分，需要补 P3 分支；P3 不显示存档写入按钮。保留搜索命中原因、错误重试、目标不存在、URL／历史和滚动行为。
4. **补齐两条双向关系。** 技能↔防具沿用现有技能身份与复制标记；材料道具↔防具新增配方反查。`P3ItemCatalogRepository` 当前明确把防具用途标为 `not-collected`，接入后按实际覆盖更新，不能只改提示。正文开一级详情抽屉，抽屉内关闭后定位对应图鉴。
5. **接续旧链接。** 技能页当前通过 `getP3SkillArmor` 和 `P3SkillArmorPreview` 落到最小预览；完整防具上线后改为完整详情／防具页定位，并兼容已有技能页装备参数，避免旧收藏或返回路径失效。
6. **离线构建与验收。** 新构建以当前含道具、装饰品和技能的完整 P3 库为基线，审计旧表、旧关系和其他作品指纹；仅扩展防具不需要重建道具词典。全量关系端点、同名条目、负点、复制标记、替代配方、缺资料状态及两种窗口尺寸列为验收点。

推荐推进顺序：原生核心数值／判定 → 制作与目录边界 → 套装和名称审阅 → 离线构建 → 查询及共享页面 → 双向关联和回归。沿已定位的 P3 消费者定向补查即可，不恢复整个武器、护石、存档或汉化研究。
