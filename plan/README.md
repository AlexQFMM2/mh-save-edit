# MH Save Editor 总体实施计划

状态：三作图鉴、技能图鉴、MHGU/XX 猎猫图鉴与配装器 3A 已完成；下一阶段转向存档桥接
计划日期：2026-09-10
目标项目：`mh-save-edit` 统一 React + Electron + TypeScript 桌面应用

## 1. 最终目标

新项目不再充当旧 Qt 修改器启动器，而是在一个代码库中提供：

1. MH3G、MH4G、MHGU/MHXX 的离线资料图鉴和对应小图标。
2. 五种模拟器存档格式的玩家信息、道具箱和装备箱编辑能力。
3. 与装备箱实例解耦的手动配装器和自动配装器。
4. 核心功能稳定后再统一完成 UI 设计和动效。
5. 复用现有 `mhed-platform` 的账号、邮箱、配装广场和管理能力。

本项目只支持模拟器使用的存档，不支持实体机原始/封装存档。支持矩阵固定为：

| 内容游戏 | 存档格式标识 | 平台 | 模拟器 | 状态目标 |
| --- | --- | --- | --- | --- |
| MH3G | `mh3g-3ds-citra` | Nintendo 3DS | Citra | 完整支持 |
| MH3U | `mh3u-wiiu-cemu` | Wii U | Cemu | 完整支持 |
| MH4G | `mh4g-3ds-citra` | Nintendo 3DS | Citra | 完整支持 |
| MHGU | `mhgu-switch-yuzu` | Nintendo Switch | Yuzu | 完整支持 |
| MHXX | `mhxx-3ds-citra` | Nintendo 3DS | Citra | 完整支持，须补真实样本验收 |

MH3G 与 MH3U 共用一套内容域，但存档布局、文件头和大小端规则不同。MHGU 与 MHXX 共用一套
内容数据来源，但保存格式、平台校验和角色槽布局必须使用独立适配器。

## 2. 实施原则

- 功能正确性优先于 UI；前三阶段只要求界面清楚、可操作、不会误改存档。
- 图鉴数据、配装数据和存档实例是三种对象，不互相冒充。
- 配装默认选择完整图鉴中的合法自然装备；“仅使用装备箱已有装备”是后续存档桥接阶段的可选筛选条件，不进入首版配装器。
- 后续从装备箱选择装备时，只提取装备定义、等级、珠子和必要实例参数，不保存箱子格号。
- 存档解析始终保留完整原始字节，只补丁用户实际修改的已知字段。
- 未修改保存必须逐字节一致；跨格式、跨游戏和损坏文件必须在写入前拒绝。
- SQLite 只保存只读游戏数据；用户配置、本地配装和在线账号状态不得写进游戏数据库。
- 在线服务故障不得影响图鉴、存档编辑、本地配装和本地文件导入导出。
- 旧项目用于迁移算法、数据生成器和测试证据，不复制 Qt 页面或继续维护多套业务逻辑。
- 所有内容 ID 都必须保留来源域，不按名称或数组位置猜测跨游戏映射。

## 3. 统一领域标识

现有空壳中的 `GameId` 不足以表达五种格式。实施阶段首先拆为：

```ts
type ContentGameId = 'mh3g' | 'mh4g' | 'mhgu'

type SaveFormatId =
  | 'mh3g-3ds-citra'
  | 'mh3u-wiiu-cemu'
  | 'mh4g-3ds-citra'
  | 'mhgu-switch-yuzu'
  | 'mhxx-3ds-citra'
```

打开文件后，界面必须持续显示：游戏、版本、平台、模拟器、文件格式和角色槽。用户首次进入编辑页
或保存前必须能明确确认当前修改的目标，不能只显示笼统的“3G”或“GU”。

UI 美化不阻止早期功能验收，在线功能也不作为本地核心能力的依赖。

## 6. 阶段 0：先冻结公共协议

### 工作项

- 定义 `ContentGameId`、`SaveFormatId`、`SaveIdentity` 和每种格式的 capabilities。
- 定义玩家、道具格、装备实例、逻辑配装、校验问题、补丁集和保存结果类型。
- 定义稳定错误码：格式不支持、文件损坏、校验失败、槽位越界、箱子已满、数据版本不匹配。
- 从三个旧修改器中建立“源实现 → 新模块 → 对应回归测试”的迁移清单。
- 冻结 `.mhloadout.json` 兼容策略以及本地/线上 `schema_version`、`data_version` 规则。
- 明确 renderer 不直接访问 Node、文件系统、SQLite 路径或认证令牌，全部通过 preload 白名单 IPC。

### 验收

- 五个格式不会再被三个宽泛的 adapter 混淆。
- 一个损坏或未知文件不会被任何 adapter 兜底认成合法存档。
- 公共模型不包含 Qt 类型、DOM 类型、文件路径或装备箱格号。

## 8. 当前明确不做

- 实体机封装存档、实体机加密容器或设备密钥处理。
- 在不同游戏之间按名称自动转换整份存档或装备 ID。
- 角色/怪物 3D 模型、试衣间和独立地图百科。
- 在线存档上传、云端修改存档、上传角色名或原始装备字节。
- 在完整规则没有证据前自动生成发掘装备、非法护石或猎虫实例。
